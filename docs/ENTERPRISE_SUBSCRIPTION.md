# 企业自托管交付与离线授权

DbSphere v4.9.0 支持企业自托管年度订阅的离线签发、续期、扩容和用量核对。社区部署可直接使用基础采集、监控、告警和规则诊断。企业交付时，在所有平台副本配置同一份授权方公钥，并在平台控制台导入绑定当前部署的授权文件。

## 交付与合同范围

| 交付项 | 需要核对的内容 |
| --- | --- |
| 年度订阅与容量 | 合同起止时间、部署数量、每部署资产上限、已登记站点上限。资产按该监控库的资产记录计数，站点按中心登记记录计数。 |
| 软件交付 | 签名离线安装介质、校验清单、授权方和发布公钥指纹、部署手册、适用的支持矩阵。 |
| 升级与支持 | 约定支持时段、变更与故障响应流程、升级窗口、备份恢复要求和回滚验证记录。 |
| 专业服务 | 根据合同另行约定实施、数据源专项验收和恢复演练。 |

付费试点签收、报价和支持排班由实际客户合同确认。数据库版本与拓扑按发布支持矩阵及客户环境的验收结果执行。 [支持矩阵](SUPPORT_MATRIX.md)

## 首次配置与导入

1. 在「系统状态 → 部署授权」读取部署编号。编号由监控 PG18 生成并保存，应用重启后保持一致。
2. 通过交付渠道核对 Ed25519 授权方公钥。原生部署在环境文件填写 `DBSPHERE_ENTITLEMENT_PUBLIC_KEY_FILE=/etc/dbsphere-native/entitlement-issuer.pem`，并让运行用户能读取公钥。容器部署在 `dbsphere-go.env` 填写 `DBSPHERE_ENTITLEMENT_PUBLIC_KEY_PEM_BASE64`，其值为 PEM 文件的单行标准 Base64 编码。每个副本只配置一种公钥来源。
3. 重启应用后，由平台管理员上传已签名的 `.license` 或 `.json` 文件，核对签名公钥指纹、有效期、序号及实际用量。在待导入状态，平台保留已有资产的运行能力，新增资产及站点需先导入有效授权。

授权方应独立保管签发私钥。正式安装包校验使用另一份发布公钥。授权方在受控的签发环境使用静态程序签发。以下文件以一个部署和一年期容量为例，交付时填写实际 UUID 与合同日期。

```json
{
  "deploymentId": "00000000-0000-4000-8000-000000000123",
  "sequence": 1,
  "issuedAt": "2027-01-01T00:00:00Z",
  "startsAt": "2027-01-01T00:00:00Z",
  "expiresAt": "2028-01-01T00:00:00Z",
  "assetLimit": 100,
  "siteLimit": 3
}
```

```bash
umask 077
./DbSphere-go-4.9.0-linux-amd64 license-issue /secure/issuer.pem claims.json > deployment.license
```

## 续期、到期与恢复

- 续期使用同一部署编号和更大的序号，在新授权生效后导入。扩容时校对新的上限和页面的已用数量。轮换签发方公钥时安排配置更新和新授权导入窗口。
- 到期、时钟偏差或验签失败时，已有资产继续采集并生成告警。历史事件及原始证据仍可查看和导出，已有资产可用原资产 ID 复检。新增资产或站点受有效授权和对应容量约束。
- 时钟检查使用应用节点 UTC 时间及监控库中的最近时间检查点。保持各副本时钟同步。整库恢复会还原备份时的授权序号和时钟检查点，恢复后应按独立交付记录核对并补导最新授权。
- 备份包括 PG18 监控库，并单独备份原部署配置、主密钥、日志原文和可信公钥。隔离恢复后核对同一部署编号、授权状态、历史事件及采样回链。 [部署与离线验签](OFFLINE_DEPLOYMENT.md)
