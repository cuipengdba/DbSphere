# DbSphere v2.26–v2.30 监控开发规划

以 v2.25.0 为基线，2.x 还剩 v2.26.0、v2.27.0、v2.28.0、v2.29.0、v2.30.0 五个小版本。v2.30.0 正式发布和核验后进入 v3.0 规划。本阶段沿用已有资产监控大屏、监控工作台、容器专题与事件调查，把值班时的首次发现、跨层排查和恢复验证接成一条操作路径。

| 版本 | 主题 | 值班人员能完成的事 |
| --- | --- | --- |
| v2.26 | 值班大屏与集群热力矩阵 | 登录后看到哪个集群、哪个实例何时异常，点击异常项即进入对应曲线和事件。 |
| v2.27 | PostgreSQL 性能深钻 | 从延迟尖峰选中时间桶，下钻到等待类型、阻塞 PID、Query ID 和计划或日志证据。 |
| v2.28 | 资源瓶颈与容器缓存专题 | 在同屏区分 PG I/O 等待、容器缓存回收、节点磁盘繁忙、卷空间不足和采集缺口。 |
| v2.29 | 同一事件全链路回放 | 拖动事故游标，对照各层信号、支持证据、反证和恢复，随时打开原始记录。 |
| v2.30 | 历史基线、值班视图与交付收官 | 用固定看板和前后对比复核变更收益，在持续采集和离线升级后复用原有调查链接。 |

## v2.26.0 值班大屏与集群热力矩阵

- [ ] 重排登录首页。顶部集中展示待处理事件、受影响实例、已恢复、采集陈旧和维护状态。中部用环境、集群、主库和备库矩阵定位热点。底部继续提供 12 张可放大的关键趋势图。
- [ ] 在集群矩阵显示可用性和采集新鲜度，支持异常优先、快速筛选、多实例连选和固定关注实例。事件入口直接定位到对应资产、时段和异常标记。
- [ ] 统一监控首页、总览、实时观测的状态色、图表图例、时间范围和放大手势。提供桌面值班与大屏全屏布局，验证 1080p、4K 和窄屏。深色默认、浅色可切换，适配减少动态效果的系统偏好。
- [ ] 刷新时保留正在查看的实例、图表、游标和滚动位置。告警、维护、缺采、陈旧和恢复有明确文字状态，异常脉冲随实际状态变化。
- [ ] 用正常、异常、恢复、维护和暂时缺采的多集群样本验收。点击每类状态和全部 12 张图，核对进入的资产和时段，验证返回、退出全屏、键盘与触屏。

## v2.27.0 PostgreSQL 性能深钻

- [ ] 增加等待热力图和资源趋势对照。时间桶点击或拖选后，同屏联动会话数、连接占用、事务吞吐、WAL、检查点、临时文件和复制延迟。突出热点桶及采集覆盖。
- [ ] 从等待类型和等待事件钻到阻塞树、等待与阻塞 PID、库及 Query ID。使用现有只读采样和统计快照，核对连接池复用、会话启动时间和统计重置。
- [ ] 将 Top SQL、同窗慢日志、执行计划前后对照放在同一选区。公开调用数、区间总耗时、平均耗时、I/O 和样本数。P95/P99 使用实际带耗时样本或可用分布数据，并显示采样口径与覆盖范围。
- [ ] 增强包补齐集群等待和 SQL 性能专项，从 DbSphere 入口继承资产、数据库和时间窗。标准包使用原生监控与下钻。
- [ ] 在 PostgreSQL 14–19 兼容矩阵上验证按版本展示能力。用真实锁阻塞、SQL 退化和统计重置演练点图到证据。覆盖扩展缺失、权限有限和数据不足。

## v2.28.0 资源瓶颈与容器缓存专题

- [ ] 增加从 PG 实例到容器、Pod、节点、PVC 和块设备的可点击视图。边上显示身份、采集来源、采样时间和映射状态。Linux 裸机路径直接进入主机和块设备。
- [ ] 将容器缓存并排升级为同尺度对照。选择一个或多个容器，按相同游标查看 `active_file`、`inactive_file`、refault、回收、脏页、写回和压力，突出重启换 ID、Pod 迁移或统计清零的时间断点。
- [ ] 增加磁盘延迟、IOPS、吞吐、平均队列深度和 PVC 容量的同期对照，并联动 PG I/O 等待、临时文件、WAL 和检查点。设备映射与容器归属按实际证据展示，共享卷使用可核对的归属范围。
- [ ] 增强包增加容器 I/O、文件缓存和节点磁盘的 Grafana 专项。保持站内登录、返回上下文和离线交付。
- [ ] 在 Linux、Docker 和 Kubernetes 测试环境覆盖磁盘压力、缓存回收、容器重启、PVC 容量变化和采集源缺失。验证原始样本、容器 ID、设备号和 PVC UID 能对应到正确时段。

## v2.29.0 同一事件全链路回放

- [ ] 在事件内提供可播放、拖动、暂停和比较的统一时间轴。将应用 Trace、服务入口、PgBouncer、PG 会话和 SQL、Linux/K8S 与容器存储按时间分轨。选中同一时刻时同步刷新时间轴、证据关系图和侧栏。
- [ ] 增加故障前、触发、峰值和恢复的差异对照。按影响资产及服务筛选，展示首次观测、标识是否匹配、采集缺口和恢复进度。跨实例事件保留各自原始 ID。
- [ ] 候选根因卡展示支持证据、反证、仍需确认的条件和结论来源。同窗线索标明关联强度，证据不足时显示待核对。原始采样、脱敏 SQL 摘要、执行计划和已授权的日志原文保留各自来源与审计。
- [ ] 统一从大屏、Grafana 专题、事件详情和日志调查进入及返回时的事件 ID、资产、时间窗与证据选区。复制链接和导出报告支持同一上下文复现。规则根因与回放可离线工作，AI 可选，摘要引用现有证据 ID。
- [ ] 用一次真实连接池排队伴随 PG 锁阻塞的故障演练。从大屏进入事件，核对等待链、阻塞样本、SQL 和恢复后曲线，并从原文回到同一个事件。另测同窗但不相关、证据缺失及跨组织权限边界。

## v2.30.0 历史基线、值班视图与交付收官

- [ ] 提供可保存的值班视图，包括资产范围、常用指标组、对比窗口和布局。分享或重新打开时根据实际资产权限加载。支持全屏值班时固定关注集群和恢复上次调查。
- [ ] 将历史基线与发布、维护及恢复记录对齐。提供前一等长窗口、昨日或上周同一时段、变更前后对照，标明分桶口径、样本数、统计重置和缺采。可从明显偏差回到原始采样及关联事件。
- [ ] 完成规模验收，加测多个工位并发刷新、查询大时间范围、采集队列推进、监控库存储中断与恢复。沿用现有 100 资产持续采集及历史数据容量用例，记录基线与新版冷暖首屏与下钻延迟、刷新流量和采集开销。
- [ ] 执行 v2.25.0 基线与 v2.29.0 前序版本的离线升级验证。分别验证标准包、Grafana 增强包及已配置 PostgreSQL 18 的原生安装。备份与回滚演练核对资产、账号、视图、采样、事件和原文链接。
- [ ] 更新使用手册和实拍截图，归档五个版本的浏览器用例与实测结果。核验 v2.30.0 发布页、产物和校验值后，整理 2.x 使用反馈、性能数据与兼容边界，接续 v3.0 规划。

## 每版验收与交付

- 维持 Go 后端、静态 B/S 前端、独立 PostgreSQL 18 长期存储，以及 Linux amd64 和 arm64 一键离线安装。增强组件按随包方式交付，部署主机读取本地镜像与资源。
- 逐页实测新增和受影响的按钮、筛选器、图表、表单、下载和返回操作，核对实际数据或持久化结果。保留 v2.25.0 全站回归用例。每个版本从上一正式版验证升级与回退，校验发布文件的 SHA-256 后独立发布。
- 在同资产、同时间窗、同事件和资产权限约束内联动图表、日志、AI 与 Grafana。标准包、模型停用、数据缺采、工作负载重启和采集器重连都进入回归用例。
