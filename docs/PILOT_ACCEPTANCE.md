# DbSphere 客户试点与签收

试点使用独立的 PostgreSQL 18 监控库、专用 Web 端口和经双方确认的测试资产。先记录被纳管数据库的版本、拓扑、权限范围与数据保留时间，再选择标准容器包、Grafana 增强包或原生 systemd 包。 [离线部署手册](OFFLINE_DEPLOYMENT.md) · [支持矩阵](SUPPORT_MATRIX.md)

## 安装和首采演示

1. 核对单文件 SHA-256，运行对应安装包的 `--check`。记录架构、可用磁盘、端口和外部 PG18 核对结果。安装后打开实际 Web 地址，比对页面版本号与安装包版本。
2. 在独立的测试 PostgreSQL 实例创建专用监控角色。通过 `psql` 执行以下命令，使用 `\password` 交互设置凭据。监控角色的权限取自现场确认的实际采集范围。

   ```sql
   CREATE ROLE dbsphere_pilot_monitor LOGIN;
   GRANT pg_monitor TO dbsphere_pilot_monitor;
   \password dbsphere_pilot_monitor
   ```

3. 打开「资产 → 批量接入」，预览并确认测试资产。先用专用角色和一组错误的测试凭据完成首采，记录失败状态。打开首采原始采样，再返回批次。
4. 在批次内编辑原资产，更新为测试角色的正确凭据，点击复检。打开复检原始采样并返回批次。登记同一资产标识、两条采样标识、权限缺口及识别的引擎版本。对试点矩阵中的其余实际引擎重复验收。
5. 下载批次验收报告用于内部签收。预览支持包，核对允许外发的字段，再下载支持 JSON。依次从故障事件打开触发与恢复证据，核对返回事件的标识。
6. 演示结束后，从试点平台删除演示资产，停止本轮临时服务。确认 PostgreSQL 角色仅用于本轮演示后，由演示实例所有者执行 `DROP ROLE dbsphere_pilot_monitor;`。下次演示重新创建测试角色，并从独立监控库开始一轮新的批次。
