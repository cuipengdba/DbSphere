# 纳管体检

从「数据库资产」打开实例，展开「纳管体检」。报告显示采样时间和实际连接结果，与上一次采样对照。可以核查数据库连接、TLS、只读会话、统计视图、Top SQL 扩展和已有的 Linux、K8S、容器、PgBouncer、Patroni 数据源。K8S Pod、Node 和 PVC 分开显示，便于找到资源范围或权限缺口。

平台管理员可展开「批量纳管体检」，选择本页最多五个资产。使用已有监控账号执行一次正常只读采集并在 PG18 保存采样。结果按处理原因分组，异常资产可用原 ID 复检。导出的体检 JSON 包含状态、时间和样本引用。

PostgreSQL 采样成功但读取跨会话统计的权限受限时，记录采集覆盖告警，数据库连通性单独判断。新的成功样本确认权限恢复后，原采集覆盖事件恢复。缺采时保留待核实状态。瀚高安全版 4.5.9 的内核限制和账号配置见[瀚高接入指南](HIGHGO.md)。

体检根据已保存的采样推导。未配置的数据源、当前内核缺少的视图、权限受限和未知状态分别显示。需要核验具体失败详情时，从报告打开有权限的原始采样。

## 批量接入与首采验收

平台管理员在「批量纳管与首采验收」粘贴 YAML、CSV 或 Pigsty 清单，预览后应用。YAML 和 CSV 每批最多 100 项，可混合 PostgreSQL、MySQL、达梦、金仓、Redis 与 etcd。清单使用环境变量或既有资产的凭据引用。新资产可设置所属组织，已有资产可用 ID 明确指定。

应用清单后，选择「验收待首采资产」。页面按子批次保存状态，每批最多五个资产、同时最多两个检查。批次可从下拉列表重新打开。首采失败或覆盖受限时，展开检查项查看原因及处理提示。使用「编辑原资产」修正连接或凭据后，点击「复检异常资产」。每行保留原资产 ID、首采结果以及最近复检结果，可分别打开原始采样。
