# Go 后端与分层工作台迁移计划

> 2026-11-17 新增需求。此文记录 V0.6.0 已交付的 Go 架构和后续仍需完成的迁移验收。

## 强制架构

- V1.0 后端使用 Go。入口为 Linux `dbsphere` 可执行文件，优先 `CGO_ENABLED=0` 编译；静态前端资源编入同一程序，通过 HTTP API 与服务端交互。浏览器不需要 Node.js。
- DbSphere 的长期监控存储仍为独立 PostgreSQL 18；被监控实例兼容 PG14–18。Linux 主机、Kubernetes PostgreSQL、PgBouncer、Patroni 只读集群拓扑、备份和 OTel Trace 由只读或明确授权的适配器采集。Patroni 双节点故障演练已在 PG14–18 独立 CI 矩阵通过，生产集群验收仍待完成。
- Docker Compose 一键部署和 Linux x86_64 一键离线包以 Go 程序 + PG18 镜像为交付物。Go 单文件原生运行模式允许连接已有独立 PG18。离线目标机不需要 Node.js、Go 编译器或包管理器；容器模式仍需预装 Docker Engine/Compose。
- V0.1–V0.5 和 V0.6 开发预览使用 Node.js 后端，是迁移前历史产物。V0.6.0 正式版使用 Go 后端与内嵌静态前端；后续仍需完成剩余功能对等、生产升级与回滚验收。

Go 版现有管理员、可选只读查看及独立审批账号。设置 `DBSPHERE_VIEWER_PASSWORD`（至少 12 字符，不能与管理员相同）后重启可启用；更换并重启可轮换，移除并重启可停用，旧查看会话随凭据变化失效。默认读取所有资产；可设置逗号分隔的 `DBSPHERE_VIEWER_ASSET_IDS`，限制其读取指定资产 UUID 的资产列表、事件、告警、通知、巡检、样本、Trace 与报告。跨资产 PG18 存储汇总拒绝读取；受限集合查询先在 PG18 按资产过滤，再在 HTTP 响应层校验归属。`DBSPHERE_APPROVER_PASSWORD` 启用只可审批事件工单的独立账号，其密码须不同于另两种账号。仍未支持组织/多用户和数据库层租户隔离，因此完整 RBAC 任务未勾选。

PG18 Go schema 版本 16/17 保存管理员写 API 的操作尝试、HTTP 结果及可解析的事件 ID。通过鉴权和 CSRF 后先写审计，再运行业务写入；审计存储不可用时拒绝执行。系统状态页仅对管理员显示最近 100 条，事件页可按同一事件 ID 展开相关操作，查看账号的读取与写入均被拒绝。审计不包含正文、查询参数或凭据；当前只能归属共享管理员角色，尚无个人身份、审批或防篡改保障。

PG18 Go schema 已追加版本 14 的可选 Trace 后端 PID 列。应用数据库客户端 Span 只有在显式提供自定义 `dbsphere.pg.backend_pid` 且与同资产近期锁等待 PID 精确相符时，才显示更强的应用 → PG 锁链候选；没有 PID 的默认链路仍为低置信度时间相关分析。升级/回滚 CI 需覆盖这一向前兼容列，真实应用故障验收仍未完成。

PG18 Go schema 版本 15 为 AI 调用审计建立按日预算索引。Go 手动 AI 分析在模型请求前写入同事件 `pending` 记录，跨重启和多实例共享默认 20 次/UTC 日限额；失败调用也占用额度。限额可配置，关闭模型不影响监控和规则根因分析；自动 AI 预警仍未实现。
Go 自动摘要可显式开启，对最近 24 小时严重开放事件在同一事件 ID 下最多分析一次。通过校验的建议写入事件时间线和报告；模型失败保留审计，规则告警继续运行。此阶段是告警辅助解读，不是预测性预警；真实模型和生产告警效果仍待验收。

当前 Go 进度：已从现有 Node 实现提取 PG18 基础 schema，Go 启动时在事务与 advisory lock 下迁移并创建当月/下月分区；空 PG18 实库验证了版本 13 和分区。管理员密码的 scrypt 哈希、AES-GCM 凭据、HMAC Session/CSRF 已用 Node 格式向量验证兼容，Go 登录、限流、同源检查与登出已实现。总览所需的十个只读列表/存储接口已经从真实 PG18 读取，包含 Node 历史库的已有数据。资产增删改及 PostgreSQL 只读采集已进入 Go，凭据不返回浏览器；PG14 本机实库验证了连接失败两次和恢复共用同一事件 ID。事件详情读取同一 ID 下的原始证据、采样与同窗 Trace，提供原始样本入口和人工确认；资产详情可读样本、时间序列、慢日志和计划。Go 支持 Linux PG 与可选 node_exporter 联合采集，初步接入 K8S Pod/Node/PVC/PV/Service/Pod 事件、可选 Pod/Node `metrics.k8s.io`、Prometheus PVC 用量和 PgBouncer SHOW POOLS/STATS 的只读采集；二十五条 PG/Linux/K8S/PgBouncer/采集器默认规则具备阈值、持续时间、启停、静默识别和事件恢复，浏览器可修改这些规则。Go OTLP/HTTP JSON 已用独立 Bearer 令牌接入，仅白名单 Span 字段按唯一 PG 资产身份入库，并与既有事件 ID 的证据图关联。K8S 的生产 PVC 指标路径与其余规则仍需验收；缺少 Pod 映射或凭据会标记采集错误，避免只采数据库就误报全局健康。**生产跨层采集、通知通道、完整根因候选与自动 AI 预警仍需后续验收**；Go 一键离线交付已进入 V0.6.0 正式版，范围见发布验收。

## 页面信息架构

Go Linux node_exporter 联合采集现可在 PG 连接失败时保留主机指标，并把 Linux 节点连入同一事件 ID 的图。本机真实 PG14/node_exporter/PG18 演练和 [21 作业 CI](https://github.com/cuipengdba/DbSphere/actions/runs/44096143595) 已通过。K8S Pod/Node/PVC/Service 和 PgBouncer 的只读适配已接入；更深的重启增量、真实 PVC 用量与故障矩阵仍待验收。

Go K8S 第一段适配器只接受 ServiceAccount 或静态 bearer token kubeconfig，拒绝执行式凭据插件与关闭 TLS 校验。TLS 模拟 API 验证了只读请求、按 Pod UID 限定事件、容器 OOM、Node/PVC/PV 信息、Pod/Node `metrics.k8s.io` 与 403 缺口；PG18 实库测试验证 PG 连接失败与近期同 Pod OOM 证据归入一个事件 ID，并在恢复时关闭。2026-11-18 又在本机 kind 中将 Go 服务部署为 Pod，使用现有只读 ServiceAccount 的自动挂载凭据，完成真实 PG18、K8S 指标和探针失败→同事件根因候选→恢复样本的闭环；该账号不能读 Secret 或删除 Pod。原外部只读 kubeconfig token 仍过期，临时 token 签发曾被自动审批阻止，本次未签发新 token。Go Compose 与离线包支持可选的只读 kubeconfig 挂载，其真实外部接入仍未验收。

Pod 重建后的纳管补充：Go 资产可只填写单 Pod 的 Deployment/StatefulSet 名称，或同时保存初始 Pod 名。初始 Pod 返回 404 时，采集器只读列出同 Namespace 的 Workload、ReplicaSet 和 Pod，以标签和 owner UID 确认归属；唯一就绪 Pod 才自动跟随，并在样本中标记原映射与解析结果。多副本同时就绪、列表超过 100 或权限缺失会报映射歧义，不会随意选 Pod。TLS 模拟 API 与本机 kind 已验证重建后旧 Pod 映射、Workload-only 映射仍能取得 PG18/K8S 成功样本；大集群分页和多副本主备映射仍待设计。

Go K8S 告警移植了 Pod 未就绪、Pod 未调度、近期调度/挂载事件、近期 OOMKilled、Node 压力及可选 Prometheus PVC 使用率规则。PG18 实库验证了 PG 连接故障恢复后，OOM 告警仍触发时同一事件 ID 保持开放，两个信号都恢复才关闭。PVC 告警的真实 Prometheus 路径仍待验收。
Go 现从同一资产的前次 PG18 样本计算 WAL 归档失败与同 Pod 重启增量；首次采样、计数回退或 Pod UID 改变保持未知。PG18 实库演练验证两条增量规则触发并在后续零增量时按原事件 ID 恢复。PVC 告警的真实 Prometheus 路径仍待验收。

Go 告警静默与维护窗现支持 B/S 创建、查看和撤销；服务端校验资产/规则、起止时间、最长 30 天和原因，所有写操作要求登录和 CSRF。PG18 实库故障演练确认锁等待告警触发时写入 `alert_suppressed`，撤销维护窗后写入 `alert_unsuppressed`，两条证据使用同一个事件 ID。告警触发、解除静默及恢复会向 PG18 持久化 Webhook/邮件投递任务；Go 后台工作器支持级别路由、Webhook HMAC、SMTP TLS、失败退避和 B/S 手动重试。未确认的严重事件超过 15 分钟会在原事件 ID 下写入一次升级证据并再次通知；PG18 实库已验证未到期不升级、静默时不升级、解除静默后只升级一次。生产通知通道仍待验收。

Go 已按 Pod 标签选择同 Namespace 的匹配 Service，并将 Service → Pod 路由关系加入事件证据图和资产详情。列表限定 100 条，权限不足或分页截断会显式标记缺口；TLS 模拟 API、PG18 实库和本机 kind 探针故障事件图均已验证，生产多节点和 PVC 用量来源仍待验收。

Go PgBouncer 适配器采用只读的简单查询协议读取 `SHOW POOLS` 和 `SHOW STATS`，仅保留映射数据库最多 100 条连接池/统计记录，不保存管理员 URL 或密码。本机真实 PgBouncer 1.26.1、PG14 与独立 PG18 联合采样测试和 [修复后的 CI](https://github.com/cuipengdba/DbSphere/actions/runs/44107307127)已通过；对应客户端等待规则进入同事件告警流程。

Go Top SQL 采集已对齐历史数据格式，扩展缺失、列不兼容或查询失败分别显示状态；只存指纹与统计量。资产页从 PG18 样本计算相邻窗口增量和退化倍数，本地 PG18 真扩展与样本退化测试已通过。Go 容量预测读取最近 30 天的每日末次成功样本，以非负增长速率中位数估计 30 天容量；不足三天时显示未知，本机 PG18 实库测试通过。Go 慢日志与执行计划写入已迁移：csvlog/jsonlog 限量导入、按资产和原始记录哈希去重、只保留时间/耗时/Query ID；执行计划只保留节点类型和数值，按 Query ID 比较结构与执行时间。PG18 实库验证了去重和脱敏，HTTP 测试覆盖登录、CSRF 与请求大小；真实浏览器已上传 jsonlog 和计划，并在同一资产页显示脱敏记录和原有事件链接；仍需五版真实日志样例矩阵。

Go 只读 PostgreSQL 诊断现覆盖 14 个分区，PG14 与 PG18 实库及真实 advisory lock 阻塞关系通过本机测试；PG15–17 交由五版 CI 确认。采集指标写入 PG18 原始样本，事件图可显示等待 PID 与阻塞 PID；独立诊断失败显示不可用原因，仍需规则告警和完整故障演练。

Go 自动采集调度已实现：Linux 与已映射的 K8S PostgreSQL 资产按配置间隔并发采集 PG、主机/K8S 与可选 PgBouncer，在 PG18 写入样本/事件；默认 Compose 启用，连接外部 PG18 的 Go 开发配置默认关闭，需显式启用，避免与历史 Node 采集并行。本机真实 PG18 演练验证自动连接失败生成同一事件入口，仍须五版与恢复矩阵 CI。

Go 部署开发路径已落地：`Dockerfile-go` 用静态编译程序与嵌入页面构建最小容器；`scripts/one-click-go.sh` 启动独立 PG18 或外部 PG18 配置；`scripts/build-go-offline-bundle.sh` 将应用和 PG18 镜像打入 Linux x86_64 自解压包，目标机以 `--no-build --pull never` 启动。[21 作业 CI](https://github.com/cuipengdba/DbSphere/actions/runs/44088758026)已验证离线安装和重装。代码与历史 Node 正式部署隔离；Go 旧开发包 → 当前包 → 旧开发包的离线升级回滚已通过 [Linux CI](https://github.com/cuipengdba/DbSphere/actions/runs/44232205949)，同一 PG18 资产、样本、事件 ID 和配置哈希保持；未来 schema 变更、功能对等与正式发布仍须完成。

根因分析迁移补充：Go 已能从同一事件 ID 关联原始样本、应用服务与父子 Span、锁链、SQL 指纹、Linux 和 K8S 拓扑。确定性候选现覆盖历史 Pod OOMKilled 关联、连接数压力、锁阻塞、Linux 内存/磁盘、PgBouncer 等待、K8S Pod 未就绪/OOM/调度、Node 压力与 PVC 高水位；每个候选显示支持证据、时间顺序与局限，管理员确认/驳回写入该事件的证据时间线。PG18 实库验证 PG 连接失败时仍保留同采样的 K8S OOM 候选和同一事件 ID；应用父 Span、慢 PG 客户端 Span 与同窗锁链样本可形成低置信度候选，缺 PID 直接映射会明示；同一事件 ID 的 SQL 计划退化候选现须同时有事前基线、新计划和同期慢日志，并在证据图给出三条可打开的来源，支持人工复核；缺任一证据不推断。**复制/WAL、SQL 退化的完整规则矩阵及真实跨层故障仍未完成，证据不足显示“未定位”**。

Go 事件页现在可下载 Markdown/HTML 复盘报告，报告列出同一事件 ID 的状态、资产、应用 Span 覆盖、根因候选及人工结论、信号缺口和最多 500 条证据时间线。报告输出证据/样本/规则 ID、受控摘要和管理员主动填写的处置备注，不导出自动采集的原始 SQL 或指标 JSON；达到时间线上限时明确提示。PG18 实库和 API 测试覆盖鉴权、脱敏、事件/样本 ID，真实浏览器完成下载验收。事件页已能记录人工诊断/处置，并要求成功样本支撑恢复验证；完整工单审批和生产处置演练仍待后续版本。

Go 可选 AI 接入已实现手动事件解读的第一段：默认关闭，配置本机 HTTP 或显式开启的外部 HTTPS Chat Completions 后才在事件页显示按钮。发送的 12 KiB 以内摘要省略资产名、服务名、人工备注及原始 SQL；模型回复须包含当前事件真实证据 ID，不符合格式或超时就返回错误，不影响规则根因候选。调用成功/失败及引用 ID 作为 `ai_invocation` 留在同一事件时间线，API Key 和回复不入库。真实外部模型、预算/保留期、自动预警及问答仍未完成；配置见 [AI 接入说明](AI_INTEGRATION.md)。

页面以值班问题处理顺序组织：**总览 → 问题事件 → 资产与实例 → 告警与通知 → 巡检与报告 → 系统状态**。总览只显示待处理事件和资产健康；资产纳管及实例指标在资产页；事件页用左侧列表与右侧证据链、根因候选和时间线；规则阈值、静默与通知在告警页；模板/任务/报告在巡检页。一个问题的所有层继续使用同一个事件 ID。

Go 总览的待处理事件数使用 PG18 全历史未结事件统计，展示最近 5 条未结事件；受限查看账号在数据库查询前按资产过滤。`/api/events` 仍保留最近 200 条兼容接口，问题事件页使用 `/api/events/page` 搜索全部已保留历史。独立实库用 205 条未结事件验证总览计数，不能把最近 200 条当成全部未结事件。

Go 资产页使用 `/api/assets/page` 按名称、主机、资产 ID 和 Linux/K8S/托管运行环境搜索，50 条一页；受限查看账号在数据库分页前应用资产范围。总览、巡检和静默表单仍读取全量资产，后续需改为聚合与按需选择，才能完成真正的大规模控制台性能验收。

资产详情把 PostgreSQL、Top SQL、慢日志、执行计划、Linux/K8S、PgBouncer、Patroni 和容量趋势组织为实际标签页，一次只显示一个监控层；资产概况和当前指标仍在标签页上方。标签支持鼠标及方向键、Home、End 切换，并在数据刷新后保留选择和键盘焦点。本机浏览器已在 1280 px 桌面与 390 px 窄屏检查可见面板、无横向溢出和控制台错误；这只覆盖该页面的交互与布局，不等于全站无障碍验收。
