# DbSphere v2.7.0–v2.11.0 监控面板开发规划

以 v2.6.0 为基线。让值班人员从全域首页看到异常实例和告警，再沿同一时间窗下钻至数据库、基础设施或事件证据。每个版本完成测试及离线验收后单独发布。

## 页面和交互

- 默认进入最近 1 小时。顶部固定组织、环境或集群、时间范围、刷新频率和实时暂停。手动框选后可固定绝对时间窗，进入专题、原始采样、Grafana 或返回总览时保留有效上下文。分享链接按访问者权限重新解析。
- 首屏采用浅灰蓝底、白色面板和深蓝标题。上方一行呈现健康摘要，中间以实例状态矩阵为主，旁边放当前告警和专题入口，下方对齐可用性与告警时间线。深色主题使用深灰蓝底，全屏值班视图保留时间、异常状态和静音控件。
- 紫蓝用于数据库负载，青色用于基础设施对照。绿、黄、红用于健康、退化、异常，灰色用于缺采或未知。状态同时用文字或图形区分。通用图包含单位、时间和来源，曲线使用同窗游标。无权限、数据过期、计数器重置或缺采按真实状态展示。
- 标准离线包提供原生面板和诊断。增强离线包继续提供 Grafana 与 Prometheus，通过对应资产、专题和时间窗联动。继承 PostgreSQL 14–18 支持、既有 PostgreSQL 19 回归与瀚高适配、Linux/Docker/Kubernetes 纳管、Go 静态部署以及独立的 PostgreSQL 18 历史存储。

## v2.7.0 全域监控总览

- [x] **27-01** 重做默认监控首页。汇总集群、实例、异常成员、开放事件和采样新鲜度。以 PostgreSQL、主机与容器、采集系统等已纳管能力组织模块入口。
- [x] **27-02** 加入可按环境和集群归组的实例状态矩阵。主库与副本、不可达、采集退化和未知状态有独立标记。提供异常排序、当前告警列表及告警数量趋势。
- [x] **27-03** 落地浅色、深色、全屏和统一时间控件。复用现有资产与事件链接，补齐总览轻量查询，并在切换筛选时取消旧请求。

**验收**　同屏演示正常主备、一个真实连接故障和一个缺采目标。在桌面首屏可定位异常对象并直达事件或实例。浅色、深色、全屏与离线加载均验收。

## v2.8.0 PostgreSQL 分层看板

- [x] **28-01** 统一从总览到集群、实例、数据库和 SQL 的入口、面包屑与返回路径。以现有资产及数据库身份解析下钻，保留组织、对象、绝对时间窗及框选位置。
- [x] **28-02** 集群首屏展示主备角色、在线状态、连接饱和度、TPS、等待、WAL 速率和复制延迟。实例页连接阻塞链和 Top SQL，数据库页按已采集的数据提供事务、读写、缓冲命中、临时文件及容量趋势。
- [x] **28-03** 打通同步游标、范围缩放和原始采样入口。区分计数器、变化率和瞬时值。SQL 默认展示按区间计算的平均耗时，扩展或授权缺失时标明对应面板状态。

**验收**　制造长事务阻塞和复制积压。从总览可沿同一时间窗看到等待会话、阻塞者或复制瓶颈并回到原选区。覆盖 PostgreSQL 14 与 18 实库及既有授权兼容回归。

## v2.9.0 主机、容器和存储看板

- [x] **29-01** 建立 Linux、Kubernetes、Docker 专题。组织 CPU、内存、网络、磁盘吞吐、IOPS、延迟和压力面板，节点设备按忙碌程度排序。
- [x] **29-02** 从 PostgreSQL 实例下钻到实际 Pod 或容器、Node、设备或 PVC。对齐容器 I/O、文件页缓存、卷余量与 PostgreSQL I/O 等待。共享设备和身份歧义按实际归属粒度展示。
- [x] **29-03** 更新增强版 Grafana 节点与存储面板，增加 PromQL 查询及返回路径验收。原生界面显示采集状态和对应指标覆盖。

**验收**　分别在 Linux/Docker 与带 PVC 的 Kubernetes 实例制造可核验的 I/O 压力。核对目标身份、磁盘与数据库等待的时间对应关系。节点或卷归属不明确时，下钻到能确认的证据层级。

## v2.10.0 告警时间线和同一事件调查

- [ ] **30-01** 首页告警趋势、实例可用性时间带和专题曲线按严重程度和影响对象显示告警、维护、恢复。点击趋势中的告警可打开相应事件，并保留故障前后的时间范围。
- [ ] **30-02** 复用现有事件 ID，沿应用、PgBouncer、PostgreSQL、节点和存储证据调查。区分直接证据、同窗关联和证据缺口。用明确的匹配条件展示 PID、Query ID、卷身份或配置变更。
- [ ] **30-03** 保留发现、确认、恢复及复盘导出路径。让告警趋势中的历史事件能返回同一实例、指标选区和证据时刻。

**验收**　至少完成真实锁阻塞和连接池或存储故障的端到端演练。从首页发现问题，经专题定位到原始证据，恢复后仍使用同一事件 ID。证据不足的因果关系保留为候选。

## v2.11.0 大盘性能与离线交付

- [ ] **31-01** 复用公共时间窗内的批量查询，按时间范围切换原始采样和小时汇总。减少隐藏面板请求，保留长窗口的峰值、缺口和原样本链接。测试频繁切换筛选、断网重连后可继续观察。
- [ ] **31-02** 分开测面板首屏、历史查询、采集覆盖率、排队 P95 和重复样本。复测 100 资产、30 秒周期，在稳态与慢目标、采集副本接管场景分别记录结果。覆盖率目标为 99%，排队 P95 目标为一个采集周期内。补做 8 小时长稳测试，并在同条件下和 v2.6.0 对比。
- [ ] **31-03** 完成 Linux amd64 和 arm64 的标准与增强一键离线包及 systemd 回归。断网下验收安装、升级、按文档回退、PG18 历史保留和证据链接。记录 Grafana 或 Prometheus 不可用时原生观察与事件调查的行为。

**验收**　用同一套资产执行总览定位、跨专题下钻、事件恢复、历史取证和离线升级。报告写明实际实例数、周期、测试持续时长、响应时间及实测容量。

v2.6.0 的本机参考值为 100 个资产在 30 秒周期下覆盖率 87.93%、排队 P95 为 61.57 秒，60 秒周期补测覆盖率 93.83%、排队 P95 为 61.40 秒。两轮没有重复样本，长期容量按本轮实测结果记录。 [v2.6.0 规模采集验收](COLLECTOR_LOAD_ACCEPTANCE.md)
