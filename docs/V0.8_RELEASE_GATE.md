# V0.8.0 可选 AI 诊断发布验收与已知限制

> 2026-11-19。此页描述 V0.8.0 的交付范围；V1.0 的生产支持门槛继续在[开发任务清单](DEVELOPMENT_TASKS.md)跟踪。

## 发布范围

- 沿用 V0.7.0 的 Go 静态服务端、静态 B/S 页面、独立 PostgreSQL 18 监控存储和一键离线容器安装包。目标 Linux x86_64 主机需预装 Docker Engine 与 Compose v2；无需 Node.js 或 Go 编译器。
- 管理员可在一个事件 ID 下请求脱敏证据摘要或提出 5–400 字的问题。模型返回的解释、检查建议、不确定性和证据 ID 由服务端校验；证据 ID 必须出现在本次发送的事件证据包里。只读查看账号无法调用 AI，页面也不展示调用入口。
- 可选严重规则告警自动摘要。自动和手动调用共用 PG18 每 UTC 日预算、事件调用审计和单次超时。手动问题与答案不落库，自动建议经校验后作为待人工核验内容存于同一事件。模型失败、未配置或预算耗尽时，采集、告警、巡检、全链路规则候选和复盘报告继续工作。
- 非模型预警包括数据库约 24 小时实际增长速率、Linux 文件系统和 Kubernetes PVC 使用率规则。增长速率不表示目标磁盘剩余时间；自动 AI 建议发生在严重规则告警之后，不是故障提前预测。

## 发布验收

| 项目 | 已验证内容 | 边界 |
| --- | --- | --- |
| 模型边界 | 本机模拟兼容 Chat Completions 服务验证本地接入、显式 HTTPS 远端配置、超时、异常输出及虚构证据 ID 拒绝 | 未用真实外部模型评价准确率 |
| 事件问答 | PG18 实库 HTTP 测试验证管理员 CSRF、问题长度、共享预算、同事件证据 ID 及问题文本不入事件记录 | 当前只向管理员开放；无细粒度多用户权限 |
| 模型关闭回退 | PG14–18、Linux/Kubernetes 故障矩阵与无模型事件页由既有 CI 和本版同提交 CI 复验；规则根因候选不依赖模型 | 单节点 kind 和 CI 测试环境不能代表生产集群 |
| 保留与审计 | PG18 记录调用类型、模型、结果和引用证据；事件清理策略可限量清理符合条件的已结事件及关联 AI 记录 | 未提供独立 AI 审计保留期，开放事件可超过保留天数 |
| 发行产物 | 同一提交的 Linux CI 产物、静态程序、许可证包与离线包附 SHA-256；发布前核对所有附件 | 物理断网服务器和生产级升级回滚留待 V1.0 |

## 已知限制

问答只能解释当前事件中已接入并出现在截断上限内的脱敏证据，不会主动查询生产数据库、执行 SQL 或变更 Kubernetes。模型建议不是确定根因；缺少应用 Trace、Linux 采集器、Kubernetes 权限或历史基线时，页面仍应显示信号缺口。模型发送的事件元数据可能由第三方处理，需由部署方选择本地模型或自行授权 HTTPS 服务。V0.7.0 的 Trace 身份映射、采样率和生产 K8S 验收限制继续适用；正式生产支持矩阵以 V1.0 门槛为准。
