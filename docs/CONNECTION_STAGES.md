# 应用连接阶段与等待

打开告警事件，选择 **根因与证据 → 连接阶段与等待**。按服务、阶段和状态筛选，通过同一事件打开应用 Trace 或数据库原始采样。应用池耗时和建连耗时来自单次调用。PgBouncer 采样显示目标数据库当时等待的客户端数。数据库锁链证据显示实际等待和阻塞 PID。

| 阶段 | 数据来源 | 关联条件 |
| --- | --- | --- |
| 应用池获取 | 应用记录的获取连接耗时与结果 | 应用声明目标地址、端口和数据库，三项在纳管实例中唯一匹配 |
| 数据库建连 | 应用记录的连接建立耗时与结果 | 直连地址或已配置的 PgBouncer 业务入口唯一匹配 |
| PgBouncer 排队 | 连接池管理端的数据库级等待客户端数 | 源自当前事件的采样。同窗请求只显示时间关系，排队耗时需应用另行测量 |
| 数据库执行与锁等待 | 应用执行 Span 和 PostgreSQL 只读锁链 | 只有采样时间处于执行窗口内且等待 PID 匹配时，才将阻塞者关联到这次调用 |

应用接入沿用 [OTLP 配置](TRACE_POOLER_INCIDENT.md)。OTLP/HTTP JSON 客户端 Span 使用 `db.system.name=postgresql`、`server.address`、`server.port`、`db.namespace`。增加以下可选属性。

- `dbsphere.connection.phase` 接受 `pool_acquire`、`connect`、`execute`。现有数据库客户端 Span 继续按执行阶段读取。建连与连接池获取阶段必须明确数据库名。
- `dbsphere.connection.outcome=timeout` 与 OTLP 错误状态同时出现时标记超时。执行阶段继续使用现有状态与后端 PID 规则。
- `dbsphere.endpoint` 接受如 `checkout` 的固定业务端点名，限 64 字符。使用稳定的业务名称，避免传入 URL、参数、账号、SQL 文本或客户标识。

应用池的获取耗时包含连接池在该次获取中执行的工作。冷池可能包含初始化新连接。若要区分它们，可分别在获取操作和底层建连处埋点。Go 演练应用设置 `DBSPHERE_DEMO_CONNECTION_STAGES=true` 可记录直连建连阶段，设置 `DBSPHERE_DEMO_POOL_SIZE=1` 可在预热的一槽连接池中复现应用池耗尽。该模式等待空闲连接的超时为 500 ms。

对已有资产事件，晚到的 Trace 在刷新时按发生时间进入同一事件视图。若接收时间缺失或 Span 结束时间领先接收时间超过 1 秒，保留阶段标记并停止跨层时间关联。若应用错误发生时数据库采集仍然健康，可通过现有外部事件 Webhook 提交应用告警。未接入应用采集时，事件仍可显示本地采样中的连接池排队和锁链。整个流程可脱网运行，应用埋点按需配置。
