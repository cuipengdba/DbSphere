# 可观测性视图与后续任务

## V1.0.12 可交付视图

- **事件证据图**：把同一事件 API 中已经记录的服务/请求、数据库调用、PostgreSQL、Linux/Kubernetes 和根因候选分层显示。箭头来自原始关系，不根据布局推断因果。可按领域筛选或搜索节点，选择节点可查看观测时间、相邻关系与有权限的原始数据链接。为保持浏览器可用，每次最多绘制 45 个节点、90 条关系，页面明确标出总数和显示数；完整关系仍可在下方文本视图查阅。
- **事件时间轴**：按告警、数据库、基础设施和处置分道展示带时间戳的事件记录，选择标记可查时间及记录 ID。最多绘制最近 60 条，完整时间线继续保留。它展示先后顺序，不将同期现象自动判为根因。
- **资产趋势**：24 小时与 7 天视图显示成功/失败采样和平均连接数。缺失的时间桶留空，连接线仅跨相邻且有值的桶；悬停可看时间和值。趋势数据直接取独立 PostgreSQL 18 监控库的聚合 API，前端没有 Node.js、图表库或外部 CDN 依赖。
- **根因证据**：图旁保留规则候选的支持项、限制、信号缺口、完整关系和人工处理入口。同一事件 ID 仍是从故障到恢复的核对单位；未接入 OTel 的环境只展示数据库及已有基础设施信号。

## 数据可信度与权限

图中的边与时间戳来自现有只读 API；图的筛选、截断与排版不改变证据。节点原始数据链接沿用服务端资产作用域与角色权限。没有数据的时间桶不补零；根因候选需要人工复核。应用 Trace 的实际采样覆盖率、各系统时钟偏差和未采集的依赖仍是未知，不能从图形密度估计。

## 后续增量任务

- [ ] **OBS-01** 在 PG18 长期库中增加可配置的指标聚合与保留分辨率，提供连接、事务吞吐/回滚、等待、锁、缓存、WAL、复制延迟及数据库容量的同轴趋势。处理计数器重置、样本缺口、版本差异和时间单位；验收应使用五个 PostgreSQL 真实版本。
- [ ] **OBS-02** 将 Linux CPU、内存、文件系统和 Kubernetes Pod/Node/PVC 的可用指标与数据库异常对齐到同一可缩放时间窗；标明采集源和缺口。没有 metrics.k8s.io 或 node_exporter 时降级显示状态证据，不伪造资源曲线。
- [ ] **OBS-03** 在 SQL/等待专题提供 Top SQL 趋势、锁阻塞关系图、慢日志与计划变更标记，并从事件图双向跳转到带相同时间范围的专题视图。
- [ ] **OBS-04** 对有 OTel 的服务显示实测调用拓扑、延迟分布和数据库 Span/后端 PID/Query ID 关联；明确采样率声明与实际覆盖率的区别。无 Trace 时数据库侧不受影响。
- [ ] **OBS-05** 为高基数或长事件加入服务端分页和图聚类，保留完整节点/边计数、可定位原始证据及作用域校验；做浏览器性能与权限验收。
- [ ] **OBS-06** 增加可保存的运营看板和时间范围分享，按资产/集群/版本筛选，支持图表导出与跨事件对比；导出要带来源、时区、聚合方式与缺失标记。

这些任务按小版本逐项交付并记录真实验收，不因界面上出现图表就视作完成。
