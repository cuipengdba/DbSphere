# DbSphere V0.4.0 发行说明

V0.4 在 PostgreSQL 14–18、Linux 和 Kubernetes 监控基础上加入巡检、备份状态、容量粗估与报告。服务端采用 B/S 架构，可由 Docker Compose 一键启动，并使用独立 PostgreSQL 18 保存长期监控数据。核心监控和巡检无需 AI 模型。

## 新增能力

- PostgreSQL、Linux、Kubernetes 和备份四类版本化巡检模板。浏览器可调整阈值、手动运行、配置计划、查看历史差异并重试失败运行；缺失指标与权限不足显示“未知”。
- PG14–18 只读诊断增加事务冻结年龄、复制槽明细及选定参数。巡检覆盖连接、锁、长事务、WAL 归档、复制槽、Linux 资源、Pod/OOM、Node/PVC 与探针事件。
- 只读 pgBackRest JSON 状态适配器展示最近成功备份、仓库状态和可选的最近尝试结果。未接入备份系统不会显示为正常。
- PG18 长期存储中的数据库容量按 UTC 日汇总，至少三天数据才给出 30 天粗估；巡检报告可下载 Markdown/HTML，附资产、样本和同期事件 ID。
- 内置 PG18 存储的 Compose 备份脚本生成自定义格式归档并验证格式；可只读挂载备份清单，在存储页显示**上报**的备份年龄和恢复点。独立 PG18 还原演练会核对资产、样本、事件及巡检数据。

## 验证范围

- [Linux 发布验收 CI](https://github.com/cuipengdba/DbSphere/actions/runs/44047383649)：六个作业通过，覆盖 42 项自动化测试、依赖审计、PG18 实库存储与恢复演练、真实复制槽 WAL 保留、内置和外部 PG18 Compose、一键备份清单挂载、PG14/node_exporter 及 PgBouncer。
- 本地 PG14–18 只读诊断兼容与真实锁链通过；真实 PG18 复制槽保留 WAL、PG14 EOL 巡检、模拟备份失败与 PVC 压力通过。
- 浏览器连接真实 PG18 存储，验证巡检模板、手动执行、历史结果、报告、容量和备份状态。注入的过期备份及最近失败尝试产生两项风险；未接入时相关结果保持未知。

## 已知限制

- 完整应用 Trace、SQL 性能洞察和跨层全链路根因分析仍属于 V0.5–V0.7。当前只在有限场景将 PG 不可用与同一 Pod 的 OOMKilled 证据归入同一个事件 ID，不能把此称为完整根因分析。
- pgBackRest 适配器读取运维侧导出的 JSON 文件；真实 pgBackRest 服务端到端导出与生产备份调度尚未验收。备份清单是作业上报信息，不等同于恢复验证。生产规模恢复时间和多副本巡检未验证。
- 容量结果仅是基于历史数据库大小的粗估，不代表磁盘剩余空间。缺少连续日数据时不预测。
- 监控 SQL 只读并有限时和行数限制；云服务和所有 PG14–18 扩展组合尚未完整覆盖。PG14 上游已结束维护，应规划升级。
