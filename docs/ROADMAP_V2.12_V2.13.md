# DbSphere v2.12–v2.13 可观测性开发规划

值班人员从总览看到哪个集群、入口或实例异常和它受到的影响，再沿同一事件和时间窗打开能核对的原始证据。v2.12 优先改善发现异常的速度和大盘表现力。v2.13 把多专题调查收拢到一次可以回放的操作里。

## v2.12.0 实时观测总览

| 开发任务 | 页面与交互 |
| --- | --- |
| 12-01 重构值班首屏 | 顶部固定组织、环境、集群和全局时间窗。首屏呈现可用性、连接与排队、活跃与等待、复制、存储压力五组信号，每组同时给当前值、短趋势和数据更新时间。异常队列按严重度和可见影响范围排序，行内给出对象、持续时间、主要异动和调查入口。 |
| 12-02 集群与入口拓扑 | 用已观测到的主备、连接池、入口、Pod、容器和卷组成拓扑。点击节点或连线，侧栏显示该对象同窗指标、相关事件和采样状态。多实例闪断可看共同入口及各实例的直连结果。仅在证据支持时绘制依赖边。 |
| 12-03 异常趋势联动 | 统一 TPS、连接、等待事件堆叠、复制延迟与 I/O 趋势的时间游标。标记首次发现、首次恢复和同窗变更，点击标记可固定范围并查看关联实例。对比故障前可用区间，并标明样本不足、采集过期和指标不支持。 |
| 12-04 全屏值班模式 | 保留浅色默认、深色切换。全屏采用高对比背景、清晰状态带和异常节点局部高亮。动效只用于状态变化和回放，暂停后保留最后一次已观测值。文件页缓存专题沿用统一时间窗，容器卡片可独立下钻到节点、PVC 和事件。 |

**验收目标**

- 在 1366×768 桌面首屏可辨认最严重异常、受影响对象及入口。在 1920×1080 全屏可查关键状态和最近异常，无需滚动寻找调查入口。
- 演练主库连接异常、副本积压和采集端断开。选中异常一次即可打开相应实例或已有事件，进入后保留组织、资产、时间窗和游标。采集中断显示最后可确认时间及数据缺口。
- 使用同环境对比 v2.11 与新首屏存储查询、API 请求量和交互耗时。首屏只读取可见内容，专题随下钻加载。断网重连后恢复原选择，刷新范围时验证旧响应无法覆盖新视图。

## v2.13.0 全链路根因调查

| 开发任务 | 页面与交互 |
| --- | --- |
| 13-01 事件首屏 | 从 v2.12 异常列表进入后，首屏给出症状、已观测的影响范围、证据最强的候选与下一条可核对证据。保持已有事件 ID；跨实例问题在主事件中保留各实例原事件和各自恢复时间。 |
| 13-02 故障回放 | 同一游标驱动应用请求、入口与连接池、PostgreSQL 会话与 SQL、Linux/Kubernetes、容器缓存及磁盘/PVC 曲线。支持故障前、触发、峰值、恢复对照。点任一节点查看其变化和值的来源并可返回当前位置。 |
| 13-03 根因证据呈现 | 将直接证据、时间相关信号、反证和缺口放进同一工作台。优先展示可验证的身份对应，例如阻塞者 PID、Query ID、同一个设备号、同一 PVC UID。时间重合只作为候选信号；取不到足够证据时明确列出还缺哪条。保留已有人工复核与规则回放能力。 |
| 13-04 原始证据与交付 | 一键打开支持结论的原样本，如锁树与会话、`SHOW POOLS`、主备回放位置、节点 I/O 或卷样本。站内 Grafana 专题继续联动原事件和固定时间窗；原生工作台使用现有规则和证据完成调查，AI 可选用于归纳与解释。复盘导出含事件 ID、证据链接、选区和恢复样本。 |

**验收目标**

- 对有直接证据的事件，值班人员从总览的异常入口起最多三次操作打开关键原始采样。刷新、复制地址、进入 Grafana 后返回，均可复现同一事件和选区。
- 演练真实锁阻塞、PgBouncer 排队、复制积压、容器 I/O 或 PVC 压力。每次保留触发和恢复样本。加入一个时间重合但身份不匹配的信号，验证页面给出反证或待核查。
- 用普通只读账号验证只显示有权限的资产和证据。在未接入应用 Trace 或 AI 的环境也可沿已有数据库、入口和基础设施记录完成调查。

## 两版共同交付验证

- Go 服务和静态 Web 控制台的功能变化均进入标准和增强一键离线包。增强包验证站内 Grafana 登录与回链。Linux amd64 和 arm64 验证离线安装、从前一版升级及历史保留。
- 以独立 PostgreSQL 18 保存历史数据。验收覆盖 PostgreSQL 14–18 以及 Linux、Docker、Kubernetes 的相应监控视图。实际指标按数据库版本和已配置采集源显示。
- 逐版用同一组真实故障复测。记录首屏发现异常耗时、从总览打开直接证据的操作数和可用证据覆盖。v2.12 验收后发布，再开发 v2.13。
