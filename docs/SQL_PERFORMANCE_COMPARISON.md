# SQL 性能对比与复测

从 PostgreSQL 或 MySQL 8.4 的「问题事件 → SQL 性能对比与复测」进入。填写资产采样中的 PostgreSQL SQL 指纹或 MySQL Digest，选择基准期与对比期。两个窗口最多各 24 小时，基准期在事件开始前结束，对比期可覆盖异常期或恢复期。点击「比较两个窗口」预览，点击「保存到原事件」保留复测证据。每个事件最多保存 20 条。

| 观测来源 | 接入要求 | 对比口径 |
| --- | --- | --- |
| PostgreSQL | 业务库启用 `pg_stat_statements`，采集账号可读取跨账号 SQL 统计，典型配置为 `pg_monitor` | 比较同一库、角色、Query ID 和顶层属性的累计执行次数及执行耗时。核对统计重置标识和数据库实例身份。 |
| MySQL 8.4 | 开启 Performance Schema 和语句统计，采集账号有权读取相应视图 | 比较同一库、实例 UUID、版本和 Digest 的累计调用与耗时。通过 `FIRST_SEEN` 核对 Digest 统计生命周期。 |

窗口对相邻样本计算计数器差值。页面显示覆盖时长、有效区间数、缺采和重置次数，从首末采样链接可回到同一事件。一窗至少需要五次有效调用。统计身份变化、部分覆盖或采样超限时，可查看各窗数据和证据，页面不计算总体倍率。MySQL 的旧采样若缺少库名或 `FIRST_SEEN`，会显示缺采。累计调用平均值与慢日志分位分别展示。

## 执行计划与慢日志

粘贴在授权环境取得的两份脱敏 EXPLAIN JSON。PostgreSQL 可使用 `EXPLAIN (VERBOSE, FORMAT JSON)`，MySQL 可使用 `EXPLAIN FORMAT=JSON`。复测不会在业务库执行输入的 SQL。使用会实际执行语句的计划模式时，按客户授权在隔离实例或只读副本演练。PostgreSQL 两份计划携带 Query Identifier 时会精确核对。MySQL 计划与 Digest 的归属由操作者核对。页面列出节点操作和估算行数。

PostgreSQL 慢日志按资产、数据库和 Query ID 取已导入的记录。MySQL 可粘贴已接入 FILE 慢日志的记录 ID，系统校验组织、资产和数据库，并按该记录的日志指纹统计。记录须包含可核对的库名。操作者负责核对日志指纹与 Performance Schema Digest 是否对应。管理员可以从结果打开日志证据。分布表显示已取得记录的中位数，P95 至少需要 20 条记录。每窗最多统计 1000 条。日志来源的阈值、权限或缺采会影响分布，验收时应保留相关配置。

## SQL 原文与证据助手

SQL 原文默认关闭。组织管理员可以在「设置 → 历史留存 → SQL 原文保留」设置 0–30 天。启用后，管理员可以在保存复测时手动附加最多 8 KiB 原文。原文加密保留，只有获准查看本事件的管理员能通过审计接口读取。停用或缩短保留期会立即限制读取，到期记录由定时任务清理。复测证据中的计划摘要、累计数值和采样链接继续可查。

启用模型后可在证据助手预览送审内容。SQL 原文不会从复测原文保留区送往模型。模型可按同一事件引用脱敏计划差异和聚合统计。未配置模型或引用无效时，可使用规则核查。完成后可按[诊断报告模板](SQL_PERFORMANCE_REPORT_TEMPLATE.md)交付。
