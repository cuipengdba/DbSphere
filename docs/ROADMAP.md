# DbSphere V0.1–V1.0 十版本功能路线图

> 规划稿，2026-11-15。十个版本是 **V0.1、V0.2、V0.3、V0.4、V0.5、V0.6、V0.7、V0.8、V0.9、V1.0**。均尚未开发或发布；版本范围和验收门槛用于后续拆分 Issue，不是发布日期承诺。

## 目标与依赖

V1.0 完成 PostgreSQL 运维监控闭环：纳管、监控、告警、巡检、SQL/锁/等待分析、应用到数据库的链路关联、证据化根因分析、处置与复盘。AI 是可选的诊断助手；任何版本的核心链路均不以模型为前提。自建 PostgreSQL 15–18 优先；云 PostgreSQL 以权限允许的信号为准。

| 版本 | 主题 | 本版主要能力 | 交付验收门槛 |
| --- | --- | --- | --- |
| **V0.1** | PostgreSQL 纳管与监控起点 | 资产模型（业务/环境/集群/实例/数据库）、只读账号接入、连接与权限检查；实例可用性、连接、TPS、数据库容量、复制基础状态；资产总览、时间序列、数据新鲜度 | 用只读账号纳管单机及主从；断开采集器时显示“数据缺失”并自告警；无模型环境可独立使用 |
| **V0.2** | PostgreSQL 监控纵深 | 会话与等待事件、锁、长事务、WAL/检查点、autovacuum、表/索引、容量增长；主机与 PgBouncer 可选采集；采集开销档位 | 能在演练环境定位连接拥塞、锁等待和 WAL 增长；未接入主机/连接池时显示能力边界 |
| **V0.3** | 告警与值班 | 默认规则包、阈值/持续时间/分级、聚合去重、静默、路由、升级、通知、事件时间线；告警规则版本化 | 模拟不可用、连接上限、复制延迟、磁盘/WAL 压力时生成一次可追踪事件，支持确认与恢复记录 |
| **V0.4** | 巡检与可恢复性 | 定时/手动巡检、版本化模板、参数与权限检查、HA/复制槽/备份状态和备份年龄、容量预测、HTML/Markdown 报告与历史对比 | 可按计划巡检并识别备份失败、复制槽膨胀、冻结风险；报告可回溯原始证据 |
| **V0.5** | SQL 性能洞察 | `pg_stat_statements` 可选接入、SQL 指纹、慢 SQL 日志聚合、耗时/调用量/IO 趋势、执行计划快照、Top SQL 与退化对比 | 对同一 SQL 的性能退化可找到时间、指纹、计划变化和资源证据；无扩展时展示可用的降级结果 |
| **V0.6** | 规则化根因分析 | 锁阻塞图、等待/会话关联、根因候选规则与证据包；覆盖连接耗尽、锁链、慢 SQL、复制延迟、磁盘/WAL、autovacuum；人工确认/驳回反馈 | 六类故障演练中输出可审查的候选结论、关联时间线和缺失数据；证据不足时明确“不确定” |
| **V0.7** | 全链路问题定位 | OpenTelemetry 应用 Trace 接入；服务、请求、数据库客户端 Span、实例、SQL 指纹与指标/日志按时间窗关联；依赖拓扑和影响面 | 在示例应用中从慢请求跳转到数据库实例与 SQL 指纹，反向查看受影响服务；无 Trace 时只呈现数据库侧链路 |
| **V0.8** | 可选 AI 分析与预警 | 本地/兼容 API 模型配置、脱敏证据包、事件摘要、解释型问答、趋势风险建议；模型调用审计、预算/超时与规则回退 | 关闭模型或模拟模型故障，V0.7 所有核心功能仍可用；AI 答案能指向证据并标明不确定性 |
| **V0.9** | 运维治理与协同 | 组织/资产范围 RBAC、工单、审批准入、审计、受控低风险操作与执行回执、变更关联、事件复盘；配置备份与恢复演练记录 | 只读用户无法执行操作；受控动作必须走授权/审批并留下审计；故障报告可从告警追溯到恢复验证 |
| **V1.0** | PostgreSQL 正式版 | 兼容性与性能优化、稳定安装/升级/回滚、部署与运维文档、标准故障演练、监控目录补齐、可访问性与国际化基础、供应链和安全检查 | 通过 [产品设计中的 V1.0 验收基线](PRODUCT_DESIGN.md#6-v10-验收基线)，发布支持矩阵、能力矩阵和已知限制 |

## 三条贯穿版本的交付线

1. **非 AI 主干**：从 V0.1 起，监控与告警使用确定性采集和规则。V0.6 根因候选也是可解释规则。AI 只在 V0.8 加入，且能关闭。
2. **采集层级**：数据库连接串提供基础信号；主机、连接池、Patroni、备份依赖相应采集；应用全链路依赖 OTel。每版都公布该版本的信号覆盖表。
3. **安全与可运维性**：从 V0.1 起默认只读、采集自监控与脱敏；V0.9 加入受控处置；V1.0 才按稳定性和兼容性门槛标记正式版。

## V1.0 之后的候选方向（不属于十版本承诺）

MySQL/其他数据库适配、跨引擎统一事件模型、更广泛的云厂商集成、复杂变更自动化、备份执行编排与高级内核观测。是否实施以 V1.0 用户反馈和维护成本评估为准。
