# 监控工作台

## 选择集群与实例

在「资产与实例」录入 PG 集群名，同一个 PostgreSQL 集群的主库和备库填写同名。这个名称是人工维护的监控分组，和 Kubernetes 集群名独立。升级前已有的资产默认显示为独立实例。成员列表按当前账号权限显示；主备和回放差距使用实际采集的记录，回放差距是主库观察到的复制端最大字节差。

从「监控工作台」选择集群和实例，切换最近 1 小时、6 小时、24 小时或 7 天。核心指标、等待分析、SQL 性能、锁和运行环境继承同一个范围；事件详情的「查看事件时段的监控」会从事件窗口打开等待分析。事件入口前后各带 15 分钟，范围上限为 7 天。核心图表标注范围内的事件开始时间，点击事件进入原问题及证据链。

## 读懂等待图

采集器在已有定时采样时读取当前纳管数据库的 `pg_stat_activity` 活跃客户会话。`pg_read_all_stats` 或包含该权限的 `pg_monitor` 用于跨会话读取。无等待事件的活跃会话独立标识。Query ID 由目标实例生成，需要目标的查询标识计算可用，缺失的 ID 会如实标注。日常采样间隔决定分辨率，采样间的短查询可能漏掉。

图例可以从等待类型进入具体等待事件，再进入 Query ID。点击可用 ID 后，在同一时间范围查对应的 `pg_stat_statements` 快照。SQL 详情依赖目标扩展和快照覆盖。每个时间桶的均值以实际成功获取等待快照的次数为分母。成功快照中没有该分组时按零计算，无有效等待快照时留空。每次采样最多保留每个维度前 80 组，图表显示当前范围前 12 组及余下已保留的分组。样本超限时页面标明缺口。等待和 SQL 聚合仅保存统计和查询标识。

## 运行环境与故障证据

Linux CPU 和内存趋势使用 `node_exporter` 样本。Linux 文件系统和 K8S Pod、Node、PVC、容器资源及事件面板使用该时间段内最近一次采样的环境快照，显示采样时间和可用数据。K8S 状态来自只读 API，资源依赖 `metrics.k8s.io` 或配置的 PVC 指标来源。历史环境快照与数据库等待同窗展示，定位因果时请打开对应事件核对原始证据。

## 交付

监控工作台由 Go 服务内嵌的静态页面提供，长期监控数据存放在独立 PostgreSQL 18。浏览器可以在离线环境正常加载页面和图表。见[一键离线部署](OFFLINE_DEPLOYMENT.md)。
