# 监控工作台

## 核对 Patroni 高可用切换

在「复制与高可用」查看 Patroni 成员、DCS 最近可见时间、Patroni 心跳、候选同步资格和时间线历史。遇到选主事件，可点击「查看切换前后」回放同窗主库变化、访问入口、回放差距和原始采样。对照优先使用切换前最后一次、切换后第一次通过主备入口检查的采样。切换观测间隔以页面选中的两条采样时间为边界。

在「代理与访问入口」填写主入口、预期主库角色和可选的备库入口。两个入口均以 PostgreSQL 只读事务查询实际后端和角色。备库入口按备库角色校验。DCS 时间来自配置的 Patroni 节点，心跳和时间线历史分别显示各自的采集结果。

## 核对逻辑复制与复制槽

在「复制与高可用 → 逻辑复制与复制槽」查看当前连接库的 publication、subscription、表同步进度和订阅应用进程。复制槽表显示归属数据库、插件、活动状态及 WAL 位置。Publication 表统计显式表绑定，并标记全表发布及分区根发布。订阅连接串及密码不会读取。

保留 WAL 由主库当前位置与槽重启位置计算，未确认 WAL 由主库当前位置与消费者确认位置计算。回放确认耗时来自发送进程近期反馈，订阅端分别显示收到的、向上游回报的和已经应用的上游位置。缺采或权限不足时对应指标留空。PostgreSQL 14 的订阅应用和同步错误计数显示为不支持。

需要读取已应用的上游位置时，在订阅数据库为监控角色授权只读视图及其状态函数。其余逻辑复制指标继续按各自的可见权限采集。

```sql
GRANT SELECT ON pg_catalog.pg_replication_origin_status TO dbsphere_monitor;
GRANT EXECUTE ON FUNCTION pg_catalog.pg_show_replication_origin_status() TO dbsphere_monitor;
```

默认在当前连接库的非临时逻辑槽持续 120 秒保留至少 512 MiB WAL 时发出告警。事件中点「查看逻辑复制槽」可回到触发采样。恢复沿用原事件 ID，可以在区间内查看触发采样、保留峰值和最新采样。应用原因由订阅侧进程、同步状态和应用位置进一步核对。

## 回放根因规则版本

在事件页选择「回放根因规则」，可在同一事件上对照事件开始时规则与当前规则。结果显示支持引用、反证、待核对项和首次观测时间。选择另一条根因规则可核对同一事件的其他候选。

管理员在「告警与通知」的根因规则工作台维护启停、最少支持引用及首次观测条件，填写原因后保存新版本。支持引用按原始引用去重。新版本用于保存后新发生的事件，历史事件和恢复复盘继续显示当时版本与人工裁定。

## 核对跨实例故障与恢复范围

「跨实例影响范围」列出同一组的主事件、每个实例的子事件及各自的恢复状态。相同代理入口在两分钟内出现同类 TCP 或 DNS 故障时，DbSphere 会核对两个资产的数据库直连和原始探测。Kubernetes Service 还要核对集群与 Service UID。事件详情可打开每个实例的原始采样和独立事件。

同窗数据库失败调用来自接入的应用 Trace，按事件所属实例统计。调用列表提供受影响服务线索。管理员可在「管理事件关联」填写主事件、子事件及原因，手动关联或拆分。各实例的事件 ID、通知、审计和证据继续归原事件，历史保留关联与拆分记录。只读账号按各资产授权查看关联。

## 将变更与事件放在同一时间窗

在事件详情选择「查看同窗变更」进入该实例的时间线。列表按时间显示事件开始、恢复及资产变更。选中一条变更可以对照原始采样，复制链接会保存资产、时间窗口、事件和所选变更。

PostgreSQL 已允许采集的参数、Kubernetes 容器镜像及已观测的路由或拓扑属性出现差异时，变更以首次观测时间记录，保留入库时间、前后值及对应采样。管理员可登记发布、维护、配置、镜像、路由和拓扑变更。人工记录独立保存发生和入库时间，显示前后 30 分钟内各自最近的采样。选择人工记录可以核对时间与辅助证据，因果仍需结合原事件分析。

## 核对代理与访问入口

在「资产与实例」打开目标实例的「代理与访问入口」，选择 PgBouncer、HAProxy 或 Kubernetes Service，录入 DbSphere 采集器所在网络可以访问的主机与端口。探测使用该资产监控账号和 TLS 设置，以只读事务读取后端地址、数据库名及主备角色。可仅观测，也可指定期望角色和要求与资产直连命中同一实例。配置保存后从下一次采样生效。

- PgBouncer 同时采集已有的只读管理端点，以 `SHOW POOLS` 显示等待客户端、活跃及空闲连接。排队与池占满按数据库和监控账号所属池判断。
- HAProxy 可选配置 CSV 统计页和指定后端。统计地址加密保存，界面仅显示配置状态。清空后端名并保存可移除统计配置。
- Kubernetes Service 使用资产所在 Namespace 的 Service DNS 或 ClusterIP 和 TCP 端口。采集器同时核对 Pod Ready、Service 端口映射和可读的 EndpointSlice。采集器所在网络会影响可达性，ClusterIP 入口需要从可访问它的网络探测。

「监控工作台」的基础设施视图展示所选时间窗最近的入口快照。事件的候选根因、拓扑边和原始样本可以回查排队、后端错位或 Pod 已就绪但入口连不上时的证据。模型为可选项。

## 选择集群与实例

全域总览显示实例状态、采样覆盖与开放事件，可按组织、环境和集群筛选。选定范围后点击「PostgreSQL 看板」或实例即可下钻。资产列表可继续按运行形态、PG 大版本及标签查找资产。

在「资产与实例」为同一个 PostgreSQL 集群的主库和备库填写同一组织、环境与 PG 集群名。PG 集群名用于监控分组。未命名的资产显示为独立实例。主备和回放差距使用实际采集的记录，回放差距是主库观察到的复制端最大字节差。

「监控工作台」打开最近选择且有权限的集群。顶部显示集群、版本、可用成员和观测主库，近期故障的成员与开始时间紧贴成员状态表。成员表分别显示 PostgreSQL 可用性和采集健康，采集过期时可用性显示待确认。点击异常成员进入该实例的等待分析。

每个所选成员的上排时间条展示 PostgreSQL 可用性，下排展示采集成功、失败与缺失。开始与恢复标记都打开原事件，在事件页可返回集群同窗。将游标移到时间条就能查看该成员在同一时间桶的状态及原始采样。成员比较同步呈现连接压力、锁等待、WAL 产生速率、复制回放差距和事务吞吐。当前主库明确时，事务图默认呈现该主库吞吐。

使用最近 15 分钟、1 小时、6 小时、24 小时、7 天或自定义时间范围。集群曲线和状态时间带共用十字游标。桌面可在图中拖选，键盘或手机也可通过起止时间固定范围。「复制链接」保存当时的实际时间窗、比较成员和游标位置。事件详情的「查看事件时段的监控」会打开同一实例，并在事件起止前后各留出最多 15 分钟，范围上限为 7 天。

从集群进入实例后，顶部层级导航会保留所选的时间窗和游标。打开「数据库与对象」，选择数据库后点击「查看此库 SQL」，可按同一个 OID 查询 `pg_stat_statements` 排名并打开 Query ID 和原始采样。SQL 统计通过当前数据库的纳管连接采集。选择其他库时，DbSphere 匹配同一 PostgreSQL 服务上该库的唯一纳管连接。点击顶部数据库层级回到同窗数据库曲线。SQL 平均耗时使用区间总耗时与调用数。

## 读懂等待图

实例概览按「连接与等待」「事务与死锁」「读写与缓存」「WAL 与检查点」下钻。图例标注统计来源及时间桶平均值、区间增量或每秒速率。原始采样入口打开所选区间末次样本。客户端连接按实例统计，事务与块命中按当前纳管连接库统计。

PG14–16 的检查点采样来自 `pg_stat_bgwriter`，PG17–19 来自 `pg_stat_checkpointer`。实例客户端关系 I/O 在 PG16–19 按实际采样显示。未启用 `track_io_timing` 时留空读写耗时。增量跨重启、角色变更、WAL 时间线变化或统计重置时留断点。

采集器在已有定时采样时读取当前纳管数据库的 `pg_stat_activity` 活跃客户会话。`pg_read_all_stats` 或包含该权限的 `pg_monitor` 用于跨会话读取。无等待事件的活跃会话独立标识。Query ID 由目标实例生成，需要目标的查询标识计算可用，缺失的 ID 会如实标注。日常采样间隔决定分辨率，采样间的短查询可能漏掉。

等待排名可以从等待类型进入具体等待事件，再进入 Query ID。点击可用 ID 后，在同一时间范围查对应的 `pg_stat_statements` 快照。SQL 详情依赖目标扩展和快照覆盖。每个时间桶的均值以实际成功获取等待快照的次数为分母。成功快照中没有该分组时按零计算，无有效等待快照时留空。每次采样最多保留每个维度前 80 组，图表显示当前范围前 12 组及余下已保留的分组。样本超限时页面标明缺口。等待和 SQL 聚合仅保存统计和查询标识。

实例概览显示阻塞、长事务和空闲事务，并可打开连接、事务和死锁趋势。等待分析可以打开峰值所在时间桶的锁链，锁树展示上下游 PID、Query ID 和事务开始时间，并提供原始采样。峰值桶无锁链时会提示数据覆盖情况。历史视图保留区间最新的 60 个阻塞快照及末次采样，并支持从锁链回到同一时刻的等待趋势。

区间 SQL 排名可按调用频率、总耗时、平均耗时、共享块读和临时块写排序。相邻可比 SQL 快照贡献增量，统计重置、采样失败和超过 10 分钟的缺口切断差值。选择前一等长窗口或昨日同时段，可以按库 OID、角色 OID、Query ID 和顶层语句标记对照可比时长及平均执行耗时。查看 Query ID 时，可以打开同窗的慢日志、计划与 PostgreSQL 客户端 Trace。Trace 匹配依据为已纳管实例、Query ID 和时间范围。

### SQL 证据与前后计划

在资产详情的「慢 SQL 日志」选择 UTF-8 csvlog（PG14 起）或 jsonlog（PG15 起）。浏览器按完整记录分批发送，保留 CSV 引号内的换行。重复导入会核对会话、行号、库名和日志时间。缺少会话或行号的记录使用原始记录摘要去重。每批独立提交，文件中断后重新选择该文件即可继续处理尚未入库的记录。建议 PostgreSQL 使用 UTC 日志时间或显式数字偏移。[PostgreSQL 日志格式](https://www.postgresql.org/docs/18/runtime-config-logging.html)

在「执行计划」导入由对应数据库导出的 EXPLAIN JSON。存在 `Query Identifier` 时逐位核对完整标识。旧快照若缺少库名，会显示待核对。前后对照按资产、入库库名和 Query ID 分组，显示扫描与连接节点数量、估算行数最大偏差倍数、执行时间和根节点临时读写块，未采得的值用横线表示。根节点统计避免将同一临时 I/O 在父子节点重复加总。SQL 根因候选会检查事前计划至故障计划时间段内是否观察到统计重置，并通过原事件链接打开脱敏日志及计划摘要。[执行计划说明](https://www.postgresql.org/docs/18/using-explain.html)

### 短时等待采样

在实例的「等待分析」或「锁与会话」中，可由管理员启动 10 秒采样。标准档每秒读取一次会话状态，增强档每 250 毫秒读取一次。两个档位都最多每秒调用一次锁关系读取，每帧最多检查 16 个锁等待进程。控制台保留计划帧数、返回帧数、权限降级、证据截断和查询往返耗时。短查询可能发生在两帧之间，往返耗时包含网络与执行时间。

采样记录 PostgreSQL 后端 PID、后端启动、事务开始、查询开始和并行主进程 PID。连接池可在同一后端上先后处理多次业务请求，PID 需要与实例和后端启动时间一起核对。锁树仅展示同一帧查到的阻塞关系，预备事务对应 PID 0。[PostgreSQL 会话状态](https://www.postgresql.org/docs/18/monitoring-stats.html#MONITORING-PG-STAT-ACTIVITY-VIEW) · [锁关系函数](https://www.postgresql.org/docs/18/functions-info.html)

从一个待处理事件进入监控并启动采样，完成后会将记录加入该事件的证据图。事件恢复后仍可用原事件 ID 回到采样和锁树。每实例至少间隔一分钟，每个事件最多保留五次关联采样。未关联事件的采样按实例保留最近二十次，事件关联采样随事件保留。采样只读，依赖目标允许读取 `pg_stat_activity` 完整状态，无需 AI 模型。

## 复制与高可用

从集群成员的回放数值或主库卡片进入「复制与高可用」。主库的 `pg_stat_replication` 按发送会话展示发送、写入、刷盘和回放 LSN，最多保留字节差距最高的 50 条。近期 WAL 的写入、刷盘和回放确认耗时分开显示，未报告耗时留空。备库使用 `pg_stat_wal_receiver` 查看接收状态，并独立显示本地接收位置与回放位置的差距。

区间可切换末次和回放差距峰值的原始采样。角色、WAL 时间线、重启和统计重置以首次观测为准，可以打开对应原始采样。WAL 产生速率跨重启、时间线或 WAL 统计重置留断点。复制槽保留量、归档和 XID 年龄来自可读取的持久化样本。历史样本缺少新字段时显示缺失。

集群复制拓扑可切换到角色、时间线、暂停、路由和采集边界的观测点。接收端报告的上游地址和发送端报告的下游地址同时匹配，且观测时差在图表时间桶内时，页面标记为双端匹配。跨较长采集间隔的记录保留观测时间。服务表并排呈现 PostgreSQL 连接地址及实际响应的后端地址和角色。可将 HAProxy 的 PostgreSQL 转发入口作为目标纳管并加上 `haproxy` 标签。PgBouncer 同时显示配置的应用入口、管理台后端列表和队列状态。Kubernetes Service 显示标签选择的 Pod 及其就绪观测。所有状态提供原始采样。

已配置的 Patroni 使用 `GET /cluster` 展示 leader 和成员；地址与端口唯一匹配该集群的纳管实例时可下钻。PgBouncer 使用只读 `SHOW POOLS` 和 `SHOW STATS`，按资产数据库展示连接池和等待，应用端点来自资产配置。

## 数据库与对象

实例主页的「数据库与对象」按可连接数据库显示容量、会话、读取块和命中块。采样最多保留 32 个数据库，以当前连接库、活动会话数和名称排序。打开具体数据库后，所选区间可查看事务、连接、扫描与索引取回的行数、增删改、缓存命中、死锁、临时文件和容量。累积值按相邻可比样本计算增量，统计重置、重启和超过十分钟的间隔切断增量。共享地址使用资产与数据库 OID，接口按账号的资产权限读取。

表和索引统计限于资产实际连接的数据库。打开同实例的其他逻辑库时，页面可跳到该库已纳管的独立连接。采样从容量、累计访问、分区与维护指标挑选至多 84 张表及 48 个索引，支持 Schema 筛选、排序、分页和对象 OID 下钻。只有可见的对象进入清单。库级块统计来自 `pg_stat_database`，对象块统计来自 `pg_statio_*`，PG16–18 的 `pg_stat_io` 提供独立的实例级客户端关系 I/O 信号。

容量排行按数据库和对象 OID 对照区间首末有效样本。重命名保留原名和 OID，存储重写保留容量变化并标记计数边界，同名重建采用新 OID。增长量附有两个原始采样。观测至少 24 小时且净增长为正时提供基于该窗口的七天线性估算。维护视图可按死元组、冻结阈值占比或 Analyze 后变化行排序。活元组和死元组为统计估计，冻结阈值采用全局设置与表级有效限制。

对象维护展示主分叉容量乘以死元组比例的空间估算。采样范围和可估算对象数在表格上方显示，行宽偏斜、空闲页和 TOAST 空间需另行核对。冻结风险分别比较 XID 与 MultiXact 年龄和有效阈值。常规 Vacuum 阈值使用表级或全局基数、比例和 PG18 及以上的可用上限。Analyze 阈值对照最近分析后的估计变更行数。[PostgreSQL 维护阈值](https://www.postgresql.org/docs/18/routine-vacuuming.html)

点击表名查看同一 OID 的手动或自动 Vacuum、Analyze 前后观察。两侧采样应属于同一数据库和存储标识，并覆盖统计中的维护时间。历史事件「查看对象维护证据」保留原始告警采样。分区统计标明目录的直接子分区数与采样覆盖，索引排行标明查询有效性、写入就绪和最近扫描信息。[索引状态定义](https://www.postgresql.org/docs/18/catalog-pg-index.html)

## 备份、WAL 与时间点恢复

在纳管实例打开「备份与恢复」。为 Go 服务设置 `DBSPHERE_BACKUP_INFO_DIR`。一键离线部署可在 `dbsphere-go.env` 设置 `DBSPHERE_BACKUP_INFO_HOST_PATH`。该目录按只读方式挂载，文件由服务账号读取。用备份作业将 `pgbackrest --output=json --stanza=名称 info` 输出原子发布为 `<资产 UUID>.json`，每个文件只包含一个 stanza。采集最多读取 1 MiB，不执行备份命令。界面保留仓库边界、全量／差异／增量依赖、最近尝试以及原始采样。WAL 归档失败事件可进入相同时间范围。

包装格式使用 `pgbackrest` 数组与可选 `lastAttempt` 对象（`status`、`at`）。`walChecks` 条目包含 `repoKey`、`databaseId`、同时间线的 `from` 和 `to`、`segmentBytes` 以及从仓库实际盘点出的 `segments`。界面展示逐段覆盖和缺失标识。单个核查窗最多 8,192 段。归档最早和最近标识只来自仓库报告。

业务库演练通过 `restoreTests` 登记。每条记录包含 `id`、`repoKey`、`databaseId`、`backup`、`isolated`、`targetAt`、`startedAt`、`finishedAt`、`beforeMarker`、`afterMarker`、`restoredCommitAt`、`afterCommitAt`、`sourceCommitAt`、`confirmedBefore` 和 `excludedAfter`。界面在仓库和数据库编号内逐层检查完整恢复链，核对恢复对象中的前置标记和目标之后应排除的标记。归档异常事件可直接打开触发采样及缺失段清单。

监控 PG18 的 `monitor-store.json` 可在已有 `backupId`、`restorePointAt`、`completedAt`、`sha256` 旁加入 `restoreTests`。每条还原验证沿用相同的时间与标记字段，并填入对应的 `backupId`、`archiveSha256`、`eventsReadable`、`configurationReadable` 和 `samplesReadable`。在「系统状态」核对独立恢复结果及归档校验值。RPO 使用本次验收的源端参考提交与恢复标记提交之间的时间差，RTO 从开始恢复到验收结束。

`restoreTests` 条目引用 `repoKey` 和已有 `backup` 标识，记录 `targetAt`、`startedAt`、`finishedAt`、`confirmedBefore` 和 `excludedAfter`。有准确来源与恢复提交时间时填写 `sourceCommitAt` 和 `restoredCommitAt` 供实测 RPO 对照。目标值用 `targetRpoSeconds` 和 `targetRtoSeconds` 设置。恢复验证在隔离实例执行。PG18 监控存储另读取目录中的 `monitor-store.json` 或原生服务配置的 `DBSPHERE_STORE_BACKUP_MANIFEST`，显示逻辑备份上报时间及恢复点。

## 页面与主题

登录页和控制台顶部均可切换浅色、深色主题。首次访问默认浅色，浏览器记住选项。总览优先显示待处理事件及异常资产。在资产页可从抽屉新增或编辑纳管配置。事件详情将根因与证据、处置、时间线与报告置于同一事件下。告警、巡检和系统设置按专题切换。

「告警与通知」的值班事件按资产和事件 ID 展示处理中及最近 72 小时恢复的记录。阈值、触发持续时间和恢复观察时间可在规则中核对。启用恢复观察后，要有连续正常的可用观测才能关闭事件。恢复观察中再次越界或缺采会重置计时。静默、值班交接、误报复核、重试和恢复验证留在事件时间线。

同一事件内同一规则每个通道只排一次触发通知。最后一个信号恢复时归并恢复通知，等待该通道所有触发通知投递完成或结束重试。网络重试沿用投递 ID。巡检的高可用、容量与采集覆盖模板可核对 WAL 缺口及缺采。Markdown 和 HTML 巡检报告保留原始样本链接及事件回放地址。

## 运行环境与故障证据

「运行环境」在同一时间范围呈现 PostgreSQL 连通性、环境变化、最近快照和资源趋势。点击变化记录或故障标记可以打开原始采样或原事件。Linux 使用 `node_exporter` 提供 CPU、内存、文件系统占用、磁盘和网络吞吐，以及可用时的 CPU、内存和 I/O 压力。CPU 和吞吐按相邻样本读取，主机启动时间变化、计数回退或缺采切断增量。

Linux 资源可下钻到块设备、网卡和挂载点。节点级 CPU I/O 等待与 PSI 分别显示。设备视图呈现吞吐、I/O 时间占比、平均队列深度、IOPS、错误与丢包。至少两次连续采样才可计算增量，采集端点变化时重新建立基线。每次采样保留最多 32 个块设备、32 张网卡及 10 个挂载点。

Kubernetes 通过只读 API 保存命名空间、Pod UID、控制器、Node 和已挂载的 PVC。按观测时间记录就绪、调度、重启计数、节点压力和 PVC 状态变化。同名 Pod 重建时按 UID 区分，资源图按 UID 分段。已启用 `metrics.k8s.io` 时可切换 Pod 总量和单容器 CPU 与内存，PVC 容量和已用量分别注明来源。资源接口缺失或受限时，已取得的 Kubernetes 对象状态和 PostgreSQL 证据继续可用。

工作负载映射按 Deployment 或 StatefulSet 所有者 UID 校验，并核对 Pod 列表与回读的 UID。运行环境页显示 Workload、控制器、Pod 和 Node 身份，保留 Pod 就绪、调度、驱逐与终止状态。节点和对象事件需与当前采样的 Pod 身份一致。容器请求和限额来自 Pod 规格，用量来自 `metrics.k8s.io`。

命名空间权限包含 `discovery.k8s.io/endpointslices` 的 `list` 时，页面显示指向当前 Pod UID 的端点及其就绪、服务和终止状态，也会指明权限缺口或可见范围截断。PVC 历史记录待绑定、已绑定、请求、容量和 PVC UID。PV 关联需核对 `claimRef` 的 namespace、名称和 UID。用量数据仅查询当前 PVC 创建后的样本。旧采样保留当时的对象身份，可从同一个问题事件打开。[EndpointSlice 条件](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/) · [Kubernetes 对象 UID](https://kubernetes.io/docs/concepts/overview/working-with-objects/names/)

### CloudNativePG

在资产中填写 Kubernetes 上下文、命名空间和 CloudNativePG Cluster 名称，使用目标 `rw` Service 作为主库入口，或指定 Pod 观测独立副本。`postgresql.cnpg.io` 组的 `clusters` 需要命名空间级 `get` 和 `list`。采集器不读取 Secret，数据库凭据沿用纳管时配置的监控账号。管理员可在「资产与实例 → 批量纳管与清单导出 → 发现 CloudNativePG 集群」预览当前命名空间，将候选填入清单并核对凭据后应用。

运行环境页显示 Cluster 条件、当前主库、目标主库、Pod 就绪、服务入口和可读取的备份时间。DbSphere 通过 `inet_server_addr()` 核对实际 PostgreSQL 后端的 Pod 地址，再对照 `pg_is_in_recovery()` 和控制器报告。当控制器状态与实际角色不同步，页面会标注该观测及其原始采样。备份插件没有在 Cluster 状态发布相关时间时，页面显示未知。[CloudNativePG API](https://cloudnative-pg.io/docs/1.30/cloudnative-pg.v1/) · [CloudNativePG 服务](https://cloudnative-pg.io/docs/1.30/service_management/)

## 全链路故障回放

事件的「查看数据库请求路径」沿同一 Trace 中可读取的父 Span 展示上游服务与 PostgreSQL 调用。经配置的 PgBouncer 入口时，显示代理匹配和调用窗口内的连接池采样。已观测的后端 PID 与同窗锁等待 PID 分开核对，匹配时可打开对应 PostgreSQL 原始样本。缺父 Span、未声明采样比例、时间异常和 PID 不符分别展示。采样比例是各服务的声明，运行时实际覆盖率仍需结合采集端指标核对。仅纳管数据库时，规则告警与根因证据仍可使用。[OpenTelemetry 父 Span 语义](https://opentelemetry.io/docs/specs/otel/trace/api/) · [PgBouncer 路由](TRACE_POOLER_ROUTE.md)

在「问题事件」打开一个事件查看首次发现、影响实例、已有信号和恢复观测。按 PostgreSQL、SQL、复制、连接池、Linux 或 Kubernetes 查阅同一事件的证据轨迹。点击「原始采样」核验保存内容，或点击「定位同窗」在对应专题标出观测时刻，再返回原事件。开始、恢复和处置记录引用同一个事件 ID。

根因卡区分直接证据、时间相关和证据不足。锁链可以解释观测到的等待关系；同一采样内的 CPU 压力、Pod 未就绪或复制回放积压，仍需验证上游机制。基础规则、原始证据、人工复核、告警和回放可离线使用。启用 Trace 或 AI 时，事件页提供已取得的信号、证据引用和待核验项。

回放可按来源、故障阶段和证据判断筛选，复制链接会携带事件 ID 与筛选项。收到 Trace 时，可以回看相同资产的应用 Span，区分已匹配的等待 PID、仅同窗、PID 未对上及接收时钟异常。连接池排队和底层阻塞可在同一事件核对，各层关系用各自的原始证据确认。报告保留故障前最近有效采样、触发及恢复采样的对照和原始链接。可比采样缺失时显示空缺，已采集的零值仍可核对。

集群趋势与实例长时段视图提供最近 30 天的小时汇总，最多同时比较五个实例。图表游标联动该小时的 PG 有效次数、采样覆盖、阻塞峰值、连接峰值及复制回放差距。可从汇总打开阻塞峰值原始采样或缩到相应一小时，继续查看专题和原始证据。

升级后，Go 服务后台分段为最近 31 天的历史构建轻量趋势索引。构建期间可继续采集，较早时段按原始采样查询，首次读取可能较慢。采样、趋势与原始链接沿用同一标识，原始数据仍按配置的保留策略保存。

最近 30 天已结束的 UTC 小时会逐步写入持久化小时汇总。分享时间窗的首尾及迟到样本影响的区段按原采样计算，以保留统计重置、缺采和区间开始时的计数器口径。在「系统状态 → 采集器」点击「查看小时汇总进度」，核对覆盖区间、待补算小时和待重算小时。峰值入口继续链接当时的原始样本。

## 采集队列与恢复

自动采集的到期时间、租约、连续失败和最近结果存放在独立 PG18。采集按配置的实例并发领取任务，每个实例有 45 秒执行预算。租约有效期为 60 秒，实例采样、告警与任务推进在同一事务写入。进程意外退出后，待执行任务保留，过期租约可被重新领取。

目标连接失败时保存一条真实的失败采样并进入指数退避。采集执行或写入失败时单独记录执行状态，并在后续尝试获取当时可读取的数据。间断时间以缺采显示。连续失败的退避最长为 5 分钟，配置采集周期超过 5 分钟时保留该周期。管理员在「系统状态 → 采集器 → 查看采集队列」可区分调度延迟、尚无采样、租约执行和退避，并核对最近结果。手动采集继续由资产页或已有 API 发起。

## 批量纳管与采集覆盖

管理员在「资产与实例 → 批量纳管与清单导出」粘贴 DbSphere YAML、CSV 或 Pigsty Inventory。每批至多 100 项及 256 KiB。先预览新增、更新、保持和冲突，确认后原子应用该批。应用前若资产配置变化，重新预览。相同 ID 或唯一主机、端口及数据库组合匹配原资产。更新保留资产 ID 及历史记录。清单可使用以下格式。

```yaml
assets:
  - name: 订单主库
    host: pg-orders.internal
    port: 5432
    database: orders
    username: dbsphere_monitor
    sslMode: require
    runtime: linux
    clusterName: orders
    credentialRef: env:DBSPHERE_IMPORT_MONITOR
```

CSV 使用同名表头，`tags` 以 `|` 分隔。省略端口、数据库、TLS 或运行形态时分别使用 `5432`、`postgres`、`require`、`managed`。Pigsty Inventory 读取 `all.children` 下的集群、`pg_cluster`、成员 `pg_seq`、`pg_role`、`pg_port` 及可选的 `ansible_host`。在界面填写默认用户名及凭据引用。已有资产可引用 `asset:<UUID>` 的同名用户凭据；环境变量引用通过 Go 服务进程环境传入。容器安装时可使用 Compose 覆盖文件的服务 `env_file` 挂入仅管理员可读的本地环境文件，更新后重建服务进程。

导出的 YAML 可导入同一部署；迁往其他存储时填写新的默认凭据引用。清单包含资产 ID、连接配置和凭据引用，PgBouncer、Patroni 连接密钥可在目标环境的资产表单重新配置。监控历史及完整凭据迁移仍使用 PG18 存储备份。Kubernetes 预览按配置的只读权限查找已指定的 Pod 或 Workload，核对对象 UID 及目标端口声明。数据库分批预检最多并发 5 个，错误保留采样或单项状态，完成后可重试失败项。PG 基础采集可以在可选资源源缺失时成功。

「系统状态 → 采集器」显示采集间隔、执行队列和近两周期新鲜度。近七日覆盖按 UTC 记录观测资产、PG 有效采样、整条采集的失败比例和指标载荷大小。PG18 的实际磁盘空间与保留策略可在「长期存储」查看。
