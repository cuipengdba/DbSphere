# 监控工作台

## 选择集群与实例

总览按集群展示可用成员、采集覆盖和开放事件。筛选支持集群或成员名称、运行形态、PG 大版本、环境、标签与观测状态。环境和标签在资产表单维护。成员范围按账号权限及当前筛选计算。点击集群名进入首屏，点击受影响成员或事件可直接下钻。

在「资产与实例」录入 PG 集群名，同一个 PostgreSQL 集群的主库和备库填写同名。这个名称是人工维护的监控分组，和 Kubernetes 集群名独立。升级前已有的资产默认显示为独立实例。成员列表按当前账号权限显示；主备和回放差距使用实际采集的记录，回放差距是主库观察到的复制端最大字节差。

「监控工作台」打开最近选择且有权限的集群。最新观测的集群身份、成员表和当前事件并排显示。成员表分别显示 PostgreSQL 可用性和采集健康，采集过期时可用性显示待确认。点击异常成员进入该实例的等待分析。

每个所选成员的上排时间条展示 PostgreSQL 可用性，下排展示采集成功、失败与缺失。开始与恢复标记都打开原事件。从事件返回时可继续查看固定时段。成员比较同步呈现连接占用、事务吞吐、阻塞会话和回放差距。成员连接列显示所选区间近期采样的微趋势。当前主库明确时，事务图默认呈现该主库吞吐。主库信号不确定时，可按成员比较。

使用最近 15 分钟、1 小时、6 小时、24 小时、7 天或自定义时间范围。监控主题共用时间范围和十字游标。桌面可在图中拖选，键盘或手机也可通过起止时间固定范围。「复制链接」可共享固定时间、资产和专题。事件详情的「查看事件时段的监控」会打开同一实例，并在事件起止前后各留出最多 15 分钟，范围上限为 7 天。点击图中故障标记或事件列表可进入原事件。

## 读懂等待图

实例概览按「连接与等待」「事务与死锁」「读写与缓存」「WAL 与检查点」下钻。图例标注统计来源及时间桶平均值、区间增量或每秒速率。原始采样入口打开所选区间末次样本。客户端连接按实例统计，事务与块命中按当前纳管连接库统计。

PG14–16 的检查点采样来自 `pg_stat_bgwriter`，PG17–18 来自 `pg_stat_checkpointer`。实例客户端关系 I/O 在 PG16–18 按实际采样显示。未启用 `track_io_timing` 时留空读写耗时。增量跨重启、角色变更、WAL 时间线变化或统计重置时留断点。

采集器在已有定时采样时读取当前纳管数据库的 `pg_stat_activity` 活跃客户会话。`pg_read_all_stats` 或包含该权限的 `pg_monitor` 用于跨会话读取。无等待事件的活跃会话独立标识。Query ID 由目标实例生成，需要目标的查询标识计算可用，缺失的 ID 会如实标注。日常采样间隔决定分辨率，采样间的短查询可能漏掉。

等待排名可以从等待类型进入具体等待事件，再进入 Query ID。点击可用 ID 后，在同一时间范围查对应的 `pg_stat_statements` 快照。SQL 详情依赖目标扩展和快照覆盖。每个时间桶的均值以实际成功获取等待快照的次数为分母。成功快照中没有该分组时按零计算，无有效等待快照时留空。每次采样最多保留每个维度前 80 组，图表显示当前范围前 12 组及余下已保留的分组。样本超限时页面标明缺口。等待和 SQL 聚合仅保存统计和查询标识。

实例概览显示阻塞、长事务和空闲事务，并可打开连接、事务和死锁趋势。等待分析可以打开峰值所在时间桶的锁链，锁树展示上下游 PID、Query ID 和事务开始时间，并提供原始采样。峰值桶无锁链时会提示数据覆盖情况。历史视图保留区间最新的 60 个阻塞快照及末次采样，并支持从锁链回到同一时刻的等待趋势。

区间 SQL 排名可按调用频率、总耗时、平均耗时、共享块读和临时块写排序。相邻可比 SQL 快照贡献增量，统计重置、采样失败和超过 10 分钟的缺口切断差值。选择前一等长窗口或昨日同时段，可以按库 OID、角色 OID、Query ID 和顶层语句标记对照可比时长及平均执行耗时。查看 Query ID 时，可以打开同窗的慢日志、计划与 PostgreSQL 客户端 Trace。Trace 匹配依据为已纳管实例、Query ID 和时间范围。

## 复制与高可用

从集群成员的回放数值或主库卡片进入「复制与高可用」。主库的 `pg_stat_replication` 按发送会话展示发送、写入、刷盘和回放 LSN，最多保留字节差距最高的 50 条。近期 WAL 的写入、刷盘和回放确认耗时分开显示，未报告耗时留空。备库使用 `pg_stat_wal_receiver` 查看接收状态，并独立显示本地接收位置与回放位置的差距。

区间可切换末次和回放差距峰值的原始采样。角色、WAL 时间线、重启和统计重置以首次观测为准，可以打开对应原始采样。WAL 产生速率跨重启、时间线或 WAL 统计重置留断点。复制槽保留量、归档和 XID 年龄来自可读取的持久化样本。历史样本缺少新字段时显示缺失。

集群复制拓扑可切换到角色、时间线、暂停、路由和采集边界的观测点。接收端报告的上游地址和发送端报告的下游地址同时匹配，且观测时差在图表时间桶内时，页面标记为双端匹配。跨较长采集间隔的记录保留观测时间。服务表并排呈现 PostgreSQL 连接地址及实际响应的后端地址和角色。可将 HAProxy 的 PostgreSQL 转发入口作为目标纳管并加上 `haproxy` 标签。PgBouncer 同时显示配置的应用入口、管理台后端列表和队列状态。Kubernetes Service 显示标签选择的 Pod 及其就绪观测。所有状态提供原始采样。

已配置的 Patroni 使用 `GET /cluster` 展示 leader 和成员；地址与端口唯一匹配该集群的纳管实例时可下钻。PgBouncer 使用只读 `SHOW POOLS` 和 `SHOW STATS`，按资产数据库展示连接池和等待，应用端点来自资产配置。

## 数据库与对象

实例主页的「数据库与对象」按可连接数据库显示容量、会话、读取块和命中块。采样最多保留 32 个数据库，以当前连接库、活动会话数和名称排序。打开具体数据库后，所选区间可查看事务、连接、扫描与索引取回的行数、增删改、缓存命中、死锁、临时文件和容量。累积值按相邻可比样本计算增量，统计重置、重启和超过十分钟的间隔切断增量。共享地址使用资产与数据库 OID，接口按账号的资产权限读取。

表和索引统计限于资产实际连接的数据库。打开同实例的其他逻辑库时，页面可跳到该库已纳管的独立连接。采样从容量、累计访问、分区与维护指标挑选至多 84 张表及 48 个索引，支持 Schema 筛选、排序、分页和对象 OID 下钻。只有可见的对象进入清单。库级块统计来自 `pg_stat_database`，对象块统计来自 `pg_statio_*`，PG16–18 的 `pg_stat_io` 提供独立的实例级客户端关系 I/O 信号。

容量排行按数据库和对象 OID 对照区间首末有效样本。重命名保留原名和 OID，存储重写保留容量变化并标记计数边界，同名重建采用新 OID。增长量附有两个原始采样。观测至少 24 小时且净增长为正时提供基于该窗口的七天线性估算。维护视图可按死元组、冻结阈值占比或 Analyze 后变化行排序。活元组和死元组为统计估计，冻结阈值采用全局设置与表级有效限制。

## 页面与主题

登录页和控制台顶部均可切换浅色、深色主题。首次访问默认浅色，浏览器记住选项。总览优先显示待处理事件及异常资产。在资产页可从抽屉新增或编辑纳管配置。事件详情将根因与证据、处置、时间线与报告置于同一事件下。告警、巡检和系统设置按专题切换。

## 运行环境与故障证据

「运行环境」在同一时间范围呈现 PostgreSQL 连通性、环境变化、最近快照和资源趋势。点击变化记录或故障标记可以打开原始采样或原事件。Linux 使用 `node_exporter` 提供 CPU、内存、文件系统占用、磁盘和网络吞吐，以及可用时的 CPU、内存和 I/O 压力。CPU 和吞吐按相邻样本读取，主机启动时间变化、计数回退或缺采切断增量。

Kubernetes 通过只读 API 保存命名空间、Pod UID、控制器、Node 和已挂载的 PVC。按观测时间记录就绪、调度、重启计数、节点压力和 PVC 状态变化。同名 Pod 重建时按 UID 区分，资源图按 UID 分段。已启用 `metrics.k8s.io` 时可切换 Pod 总量和单容器 CPU 与内存，PVC 容量和已用量分别注明来源。资源接口缺失或受限时，已取得的 Kubernetes 对象状态和 PostgreSQL 证据继续可用。

## 全链路故障回放

在「问题事件」打开一个事件查看首次发现、影响实例、已有信号和恢复观测。按 PostgreSQL、SQL、复制、连接池、Linux 或 Kubernetes 查阅同一事件的证据轨迹。点击「原始采样」核验保存内容，或点击「定位同窗」在对应专题标出观测时刻，再返回原事件。开始、恢复和处置记录引用同一个事件 ID。

根因卡区分直接证据、时间相关和证据不足。锁链可以解释观测到的等待关系；同一采样内的 CPU 压力、Pod 未就绪或复制回放积压，仍需验证上游机制。基础规则、原始证据、人工复核、告警和回放可离线使用。启用 Trace 或 AI 时，事件页提供已取得的信号、证据引用和待核验项。

## 交付

监控工作台由 Go 服务内嵌的静态页面提供，长期监控数据存放在独立 PostgreSQL 18。浏览器可以在离线环境正常加载页面和图表。见[一键离线部署](OFFLINE_DEPLOYMENT.md)。
