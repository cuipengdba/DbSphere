# 日志分析

管理员在 DbSphere 中打开「日志分析」，创建项目和实例，再建立分析批次。实例可以关联同一组织的纳管资产，也可用于离线导入。在批次中填写日志覆盖和采集说明，便于识别慢日志或抽样数据。

## 导入和查看记录

1. 选择同一实例的轮转日志文件。节点之间的文件分组提交并填写来源节点。单文件上限为 512 MiB，浏览器按 1 MiB 上传分块。
2. 确认格式预览。对有明确时间和日志级别的文本日志可试用自动识别。定制前缀可填写 `log_line_prefix`，无时区的时间按选定时区解析。CSV 引号内的多行 SQL 作为一条记录。
3. 上传结束后服务端解析文件。部分解析时可筛选「未识别」记录。无法识别时可选择格式、前缀和时区重新解析。重复来源文件显示原分析批次。
4. 可按记录类型、应用和时间筛选分析明细。SQL 模板将字面量归一化，管理员可通过「查看原文」打开准确记录及少量相邻上下文。每次原文访问写入审计。

| 产品 | 导入格式 |
| --- | --- |
| PostgreSQL 14–19 | 带时间戳的文本、CSV。具备 `jsonlog` 的版本支持 JSON Lines。 |
| 瀚高安全版 4.5.9 | CSV、带 PostgreSQL 风格时间、级别和前缀的文本。 |
| 金仓 KingbaseES V9 | CSV 与带时间、会话及日志级别的自定义文本前缀。 |
| 达梦 DM8 | SQL 跟踪文本与可识别的运行日志。跟踪记录中的耗时按原单位换算，简版跟踪保留语句信息。 |

文件支持范围以发行版的样例验收为准。原始行无法解析时在批次中呈现采集覆盖。历史资产详情中的轻量慢日志仍可查阅。

## 全景报告

批次全景显示分时 SQL 速率、耗时分位数、错误、锁、显式事务及适用的引擎专题。Application 矩阵按记录中的应用名统计 SQL 耗时、锁等待、错误与临时文件。使用具有原始进程或会话标识的记录查看等待者与阻塞者。关联了纳管资产且可核对同一计数器来源时，报告提供对应实例数据库的同期 TPS。报告注明已记录的语句量、定时样本数及用户选定的日志覆盖范围。

## 存储与权限

长时存储继续使用 PostgreSQL 18。原始日志进入独立的 Zstd 压缩块表，查询与筛选读取结构化记录及索引。原始文件块随数据库备份保存，可在恢复后通过同一批次和记录 ID 读取。不同组织的管理员按组织边界查询项目与源记录。

分析结果的记录数为已导入并去重的记录量。慢 SQL 卡片统计已记录且耗时至少一秒的语句。原始上下文可以含有配置所记录的 SQL、参数或其他敏感内容，读取权限与审计沿用平台组织模型。

## 跨批次优化对比

在同一实例下选择当前批次，以「跨批次对比」选定基线。报告以 SQL 指纹、锁对象或错误码对齐，并列附带两个批次的原始样本。出现采集阈值、时间跨度或工作时段差异时，覆盖说明会标出原因。只有可比采样中同一 SQL 确实被执行并验证不再超阈值时，才把曾反复超阈值的 SQL 标记为已解决。当前批次无匹配记录时显示本批次未检出。

项目健康视图按项目展示近期批次评分。评分 v1 使用慢 SQL 占已计时 SQL 的比率、每小时错误数、每小时锁等待和死锁事件三项。低覆盖、样本不足或采集口径未知时，该批次得分留空。
