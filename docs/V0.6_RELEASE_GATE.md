# V0.6.0 正式版发布门槛

当前已发布 [V0.6.0 RC1](https://github.com/cuipengdba/DbSphere/releases/tag/v0.6.0-rc.1)。RC1 的[发布提交 CI](https://github.com/cuipengdba/DbSphere/actions/runs/44433132016)通过，六个发布文件已上传；**V0.6.0 正式版尚未发布**。本表按[任务 06-01 至 06-07](DEVELOPMENT_TASKS.md)跟踪仍需完成的验收，后续版本不能先于 V0.6.0 正式版发布。

## 八类真实故障闭环

每类需从真实故障触发，经同一个事件 ID 读取原始样本、告警、跨层证据图和候选，再在恢复后用新样本关闭原事件；缺少因果证据时必须保持“未定位”或低置信度假设。注入式规则测试用于回归，不能替代真实故障演练。

| 故障类别 | 已有实测 | V0.6.0 尚需验收 |
| --- | --- | --- |
| 连接耗尽 | Linux CI 对真实 PG18 维持连接压力超过默认 120 秒，验证同事件候选、报告和恢复。 | 补充连接拒绝与应用影响的证据边界；确认候选不把高利用率直接写成已证实故障。 |
| 锁阻塞链 | PG14–18 真实 advisory lock、只读 `pg_blocking_pids` 与 Go 应用 Trace/PID 关联。 | 在 Go 事件中演练解除锁后的告警恢复和原事件闭环。 |
| 慢 SQL / 计划变化 | PG18 真实 SQL 耗时退化；脱敏慢日志和计划导入能产生有证据的候选。 | 让真实查询、真实计划变化、慢日志与同一事件完成触发和恢复；核对 Query ID 与时间窗。 |
| 复制延迟 | 独立 PG18 主备真实暂停回放，超过默认 120 秒后触发同事件候选，恢复到零延迟并关闭原事件。 | 复核备库侧原始 WAL 信号、事件页和导出报告。 |
| 磁盘 / WAL | 真实 WAL 归档失败及恢复已在隔离 CI 演练；Linux 磁盘告警与候选有注入式测试。 | 在受控 Linux 文件系统上实测容量压力，验证 PGDATA/WAL 到挂载点映射缺口。 |
| autovacuum | 隔离 CI 演练真实关闭、告警、候选及恢复。 | 核对表积压与业务慢请求之间没有被虚构为因果关系。 |
| K8S OOMKilled | 本机 kind 真实 PG18 Pod OOM、应用 HTTP 502、Trace/PG/K8S 同事件候选和新 Pod 恢复。 | 在另一隔离环境复跑，并保留只读权限、时钟和影响面证据。 |
| PVC 压力 | 规则、候选及缺失指标降级有注入式测试；kind 已验证 PVC/PV 绑定读取。 | 接入真实 PVC 使用率信号，制造可恢复的容量压力，验证同事件证据和恢复。 |

## 其余必须通过的门槛

- 证据图与原始数据链接覆盖锁、会话/等待、SQL、复制/WAL、Linux、Pod/Node/PVC；事件、证据、样本的来源和时间可追溯。
- 八类候选逐类核对匹配条件、反证、时间顺序、缺失信号与人工确认/驳回；反证不足时明确标出，不能自动宣称根因已证实。
- 在 Linux x86_64 物理断网或网络完全隔离的目标主机上，使用 RC1 同类 `.run` 与 `.sha256` 一条命令安装，并验证 PG18 数据持久化。现有 `--network none` 容器验收证明安装器进程不联网，但 Docker 守护进程仍在有网络的宿主机。升级、应用回滚、PG18 备份恢复已在联网 CI 演练；物理断网环境的完整升级/回滚与恢复列为 V1.0 验收。
- V0.6.0 发布提交的 PG14–18、Go/PG18、K8S、离线包、安全与升级 CI 全绿；从同一提交生成、校验并上传正式产物，更新 README 当前版本徽标和完整功能说明。

正式发布后才开始 V0.7.0 的应用到数据库链路发布验收；之后依次为 V0.8.0、V0.9.0、V1.0.0。
