# DbSphere 全版本开发任务归档

> 2026-11-15 建档。此清单覆盖 V0.1–V1.0 的计划开发工作。`[ ]` 未完成、`[x]` 已完成；仅代码、文档和验收证据齐备后勾选。任务 ID 稳定，可映射 GitHub Issue。各版本继承 PG14–18、Linux、K8S 中的 PostgreSQL、B/S 架构四项约束。

## 贯穿全程的工程任务

- [ ] **C-01** 统一事件模型：事件 ID、时间窗、资产、证据节点、关系、根因候选、人工结论和恢复验证；所有告警/巡检/Trace 均可归入事件。
- [ ] **C-02** PG14–18 兼容矩阵：每版使用五个大版本执行连接、采集、SQL 兼容和升级回归；界面标记 PG14 EOL。
- [ ] **C-03** Linux/K8S 双运行环境资产模型：统一实例身份，关联 Host 或 Namespace/Workload/Pod/Node/PVC，支持映射缺失状态。
- [ ] **C-04** B/S 安全基线：浏览器控制台 + HTTP API，Linux/Linux 容器部署，TLS、会话、权限、审计、脱敏和无默认弱口令。
- [ ] **C-05** 采集能力矩阵：按版本、权限和接入模式显示可采集、不可采集、陈旧与错误；限制采集负载。

  资产详情现按实际样本列出数据库基础指标、深度诊断项数、Top SQL、Linux/K8S、PgBouncer 和 Patroni 的已采集/未采集/未接入/不适用状态，并沿用采样新鲜度；托管模式明确缺少主机/K8S 信号。自动采集每轮最多 100 个资产、默认 4 个且最多 16 个并行工作，每目标仍限 45 秒；并行上限有单元验收，[本机 20 资产两轮冒烟](COLLECTOR_LOAD_ACCEPTANCE.md)通过。按版本/权限的完整能力矩阵、实测目标开销、生产规模压测与多副本租约仍待完成。
- [ ] **C-06** 可复现故障实验：单机、主从、K8S PG 和示例应用；覆盖连接、锁、SQL、WAL/磁盘、复制、OOM、PVC。
- [ ] **C-07** 质量流水线：格式/静态检查、单元与集成测试、依赖许可和安全扫描、Linux 构建；发布前性能与恢复演练。
- [ ] **C-08** 文档与发行：部署、权限、采集开销、兼容矩阵、升级/回滚、故障演练和已知限制持续维护。
- [ ] **C-09** 容器化一键部署：Linux Docker Compose 单命令启动、自动生成独立密钥、健康检查、持久卷、升级/回滚与失败诊断；不使用默认弱口令。
- [ ] **C-10** PG18 长期存储：独立于被监控业务库，保存资产、样本、事件、证据与后续 Trace 索引；迁移、分区、保留期、备份恢复和容量基线可验证。
- [ ] **C-11** Go 后端与静态前端：V1.0 服务端全部由 Go 承担，静态页面调用 HTTP API 并随 Linux 单文件一起交付；旧 Node 版迁移、数据兼容和功能对等验收见[专项清单](GO_UI_MIGRATION.md)。
- [ ] **C-12** 分层运维工作台：总览、事件、资产、告警、巡检和系统状态分区，事件 ID 全链路优先，桌面/窄屏浏览器验收见[专项清单](GO_UI_MIGRATION.md)。

## V0.2：PG、Linux 与 K8S 纵深观测

- [x] **02-01** PG 会话、等待、锁链、长事务、WAL/检查点、autovacuum、表/索引容量采集，按 PG14–18 差异适配。五版均通过 11 个诊断分区查询与真实 advisory lock 阻塞链演练。
- [x] **02-02** Linux CPU/内存/磁盘/IO/网络采集器，标记权限与开销，不在目标主机执行任意用户脚本。通过只读 node_exporter `/metrics` 采集，4 秒超时、5 MiB 上限；真实 PG14 + node_exporter + PG18 存储演练已验证速率与重启持久化。
- [x] **02-03** K8S 只读凭据、Namespace/Pod/Container/Node/PV/PVC/Service 发现，按 OwnerReference 和标签关联 PG 实例。Namespace 限定并限制单类资源最多 100 项；只读 ServiceAccount 的真实 kind 演练已验证 Pod → ReplicaSet → Deployment、Service 标签、Node、PVC/PV 关联。未授权资源和截断结果显式显示。
- [x] **02-04** 接入 K8S Pod 重启、状态、驱逐、OOMKilled、调度、探针、Node 压力、PVC 用量和事件；区分 API/metrics-server/exporter 来源。真实 kind 已验证容器重启、Pod/Node 条件、metrics-server 和探针失败 `Unhealthy` 事件；驱逐/OOM 状态用适配器测试验证。PVC 容量来自 K8S API，实际用量连接可选 Prometheus kubelet 指标并通过模拟响应验证；测试集群未提供该真实指标，界面明确显示未采集。
- [x] **02-05** PgBouncer 可选适配与 Linux/K8S 资源趋势联动；不可用信号显式标记。加密连接串、只读 `SHOW POOLS/STATS`、同资产 PG/Linux/K8S 联合采样与事件证据已实现；真实 PG14 + PgBouncer + PG18 存储通过本地和 Linux CI。
- [x] **02-06** 验收：从 PG 实例跳转到其 Linux 主机或 K8S Pod/Node/PVC，模拟锁等待、Pod 重启与采集权限缺失。浏览器资产页分层跳转已演练；PG14–18 真实 advisory lock 阻塞链、kind 容器重启/探针失败及只读账号的资源权限缺口已验证。
- [x] **02-07** PG18 持久化后端：资产、凭据、样本、事件和证据以独立 PG18 为正式存储；提供 SQLite 预览数据迁移与校验，禁止监控数据写入被纳管业务库。真实 PG18 容器与 Linux CI 已验证重启持久化、事件证据、凭据重加密和旧版 SQLite 数据导入。
- [x] **02-08** Linux Docker Compose 一键部署：DbSphere + PG18 两容器、随机初始密钥、数据卷、健康门禁、只暴露 Web 端口；支持改用现有 PG18 实例和可选只读 kubeconfig 挂载。默认与外部 PG18 两种模式均通过 GitHub Linux CI。
- [x] **02-09** 验收：一条命令安装、首次登录、纳管 PG14–18 或 K8S PG；重启/更新后 PG18 中资产、样本、事件和证据一致；错误配置清晰失败。[Linux CI](https://github.com/cuipengdba/DbSphere/actions/runs/44020986662) 验证默认与外部 PG18 Compose、PG14 真实目标、登录、更新与存储故障、K8S kubeconfig 挂载、无效路径和 PG17 存储拒绝；PG14–18 的数据库采集兼容另由五版矩阵与 kind PG18 验证。生产规模升级与备份恢复仍在后续版本范围。

## V0.3：跨层告警与值班

- [x] **03-01** 规则表达式、持续时间、严重度、去重键与版本管理；提供 PG14–18 默认规则包。V0.3 使用受控指标名 + 比较运算符 + 阈值的规则表达式，规则修改递增版本；按资产与规则持久化状态，告警在同一事件组中去重。默认规则覆盖 PG14–18、Linux、K8S、PgBouncer；不执行任意表达式代码。SQLite/PG18 持久化、浏览器编辑与 CSRF 验证已通过。
- [x] **03-02** PG 不可用、连接、复制、锁、WAL/磁盘，Linux 资源与 K8S Pod/OOM/PVC/Node 告警。受控默认规则覆盖上述信号；缺失或无权限的指标显示不可用，不触发资源正常结论。规则及阈值可在浏览器编辑。
- [x] **03-03** 同一故障的多条告警关联一个事件 ID；时间线保留触发、确认、抑制、恢复和证据。SQLite/PG18 的事件归并、状态变迁和确认已通过自动化测试；浏览器验证维护窗内外的同一事件时间线。
- [x] **03-04** 静默、维护窗、通知路由与升级；至少一个通用 Webhook 和邮件通道。两个通道均有持久化投递、级别路由、失败重试和人工重试；未确认严重事件在同一事件 ID 下升级一次。Webhook HMAC 和本机真实 SMTP 协议会话通过测试；生产 SMTP 与多副本投递留待后续验收。
- [x] **03-05** 采集器失联、数据陈旧与权限变化作为独立状态告警，禁止用缺失数据得出“健康”结论。PG、Linux、K8S 采集错误和超过两个周期的陈旧样本有独立规则；PG 鉴权/权限失败归采集故障，PG 可用性保持未知。K8S 未授权资源与未配置采集器显示数据缺口。Go 控制台根据服务端采集开关、周期与时间计算展示状态；关闭自动采集时只称“最近一次成功”，开启后超过两个周期称“数据陈旧”。
- [x] **03-06** 验收：PG 故障与 K8S Pod 重启同时发生时，按资产和时间窗形成可审查事件，不错误合并无关问题。PG 不可用与同一 Pod 的近期 OOMKilled 共用事件 ID；无关 PVC 风险保留独立事件。PG18 实库与自动化测试通过。
- [x] **03-07** PG18 样本/事件按时间分区、保留期策略和聚合查询；展示存储占用与预计增长，保留期不误删未结事件证据。真实 PG18 月分区、旧表迁移、小时聚合、保留期清理及未结事件保护通过 Linux CI；浏览器显示容量与粗估增长。默认不自动清理，批量分区卸载及生产规模备份恢复留待后续版本。

## V0.4：巡检与可恢复性

- [x] **04-01** 巡检模板版本、规则执行、计划调度、手动执行、历史差异与失败重试。PG18/SQLite 持久化模板、计划和巡检历史；浏览器可修改阈值发布新版本、立即巡检、启停定时计划、查看与上次结果差异及重新巡检。采集忙或内部执行失败归档为可重试失败记录；缺失数据标未知。自动化接口与真实 PG18 实库、浏览器手动流程通过。
- [x] **04-02** PG14–18 参数/权限/冻结/复制槽/HA 检查；SQL 采集只读且有超时与开销限额。采集 `pg_settings` 选定参数、`datfrozenxid`、复制槽活跃/失效/WAL 保留、监控权限及主备复制信号；巡检按角色标注不适用。查询在只读会话中受 3 秒 statement timeout、5 秒客户端 query timeout 和行数上限约束。五版真实只读采集与锁链、PG14/PG18 巡检验证通过。
- [x] **04-03** Linux 系统资源、文件系统与权限检查；K8S 工作负载、探针、Pod、PVC、事件检查。node_exporter 资源及 401/403 权限异常、Pod Ready/OOM、Node 压力、PVC 用量/绑定、近期探针和调度挂载失败事件进入版本化巡检；缺失 API 或指标保持未知。真实 kind 探针事件来源由 V0.2 演练验证，巡检判定由注入信号测试覆盖。
- [x] **04-04** 备份适配器与备份年龄/失败检查，区分“未接入备份系统”和“备份正常”。只读 pgBackRest `info --output=json` 文件适配及可选调度器最近尝试状态；分别检查最近成功备份年龄、仓库状态和尝试失败。未接入/缺文件/无备份/未提供尝试状态均显示未知；文件边界及故障用自动化测试覆盖。真实 pgBackRest 服务端到端导出仍是已知验收缺口。
- [x] **04-05** 容量增长与保守趋势预测，报告输出 Markdown/HTML 并关联资产、事件和原始证据。正式 PG18 存储按 UTC 日取近 30 天数据库容量样本，至少跨 3 日才给出基于日增长速率中位数的 30 天粗估及置信级别；巡检报告可下载 Markdown/HTML，保留资产、巡检、样本和同期开放事件 ID。无数据明确标注无法预测，预测不代表磁盘剩余空间。实库查询、接口和浏览器验收通过。
- [x] **04-06** 验收：复制槽膨胀、备份失败、PVC 压力和 PG14 EOL 均产生正确巡检结果。真实 PG18 物理复制槽保留 WAL 触发巡检风险，PG14 容器返回 EOL 风险；备份失败和 PVC 压力由受控输入测试验证，保留来源和未知状态。
- [x] **04-07** PG18 存储的备份、恢复与迁移演练；明示备份年龄和恢复点，不将“未配置备份”标为正常。独立 PG18 数据库的 `pg_dump`/`pg_restore` 演练核对资产、样本、事件和巡检记录；一键 Compose 内置存储的备份脚本、归档格式验证、清单只读挂载及状态接口通过 Linux CI。页面仅显示清单上报的年龄和恢复点，缺失时为未知，不将其等同恢复验证。生产自动备份计划及生产规模恢复时间仍需运营方验证。

## V0.5：SQL 性能洞察

- [x] **05-01** 检测 `pg_stat_statements` 可用性与权限；兼容 PG14–18 字段差异，未启用时优雅降级。目标库只读检测扩展、视图字段与统计重置时间；真实 PG14–18 五版采集通过。缺扩展、未预加载或权限不足给出不可用状态，不影响基础监控。
- [x] **05-02** SQL 指纹与指标聚合：调用、总耗时、平均/可用分位、读写、临时文件、趋势；避免高基数爆炸。每资产只保留累计耗时前 50 个指纹，API 显示 Top 20；采样增量覆盖调用、总/平均耗时、共享块读写、临时块读写、WAL 与行数，并有最多 12 个窗口趋势。扩展不提供分位数，明确不展示虚构 p95/p99；原始 SQL 正文不采集。
- [x] **05-03** 慢 SQL 日志导入与脱敏，关联实例、时间窗和指纹；限制语句正文展示权限。管理员可按资产导入 PG14–18 CSV 或 PG15–18 JSON 日志片段，按数据库筛选、原始记录哈希去重，只存时间/耗时/精确 Query ID，不存语句正文与参数；缺 Query ID 显示未关联。写操作受登录与 CSRF 保护。
- [x] **05-04** 执行计划采集采用显式触发或已有日志，不在生产库上自动运行高风险 `EXPLAIN ANALYZE`。管理员手动导入已有 `EXPLAIN (FORMAT JSON)`，仅持久化节点类型及数值，过滤表达式和对象名不入库；同 Query ID 计划结构及已有执行时间可比较。五版真实只读计划解析通过。
- [x] **05-05** Top SQL、退化对比与事件证据链接；可看到 SQL 变化与 Linux/K8S 资源变化的时间关系。两段相邻窗口具备最少调用数及绝对/相对退化门槛；真实 PG18 延迟演练触发提示。页面在采样时间点并列 SQL 平均耗时、Linux CPU/内存、K8S Pod 状态/重启，并关联资产的开放事件；慢日志与计划按五分钟时间窗关联事件，不把时间相关性视为因果证明。
- [x] **05-06** 验收：五个 PG 大版本的可用视图测试、SQL 退化演练和无扩展降级测试。[Linux 发布验收 CI](https://github.com/cuipengdba/DbSphere/actions/runs/44053161066) 11 个作业通过，五版真实容器均先检查未安装扩展的降级，再创建扩展采集指纹；PG18 真实五次快查询/慢查询形成退化提示。本地 49 项自动化测试及 B/S 浏览器导入流程通过。

## V0.6：一个问题的跨层根因分析

- [ ] **06-01** 证据图存储与查询：事件 → 告警 → 指标/日志/SQL/等待/锁 → Linux/K8S 资源/变更；保留时间与来源。
- [ ] **06-02** 锁阻塞链、会话/等待聚合、主从与 WAL 关联；所有节点可返回原始数据链接。
- [ ] **06-03** 确定性根因规则：连接耗尽、锁链、慢 SQL/计划变化、复制延迟、磁盘/WAL、autovacuum。
