# DbSphere 全版本开发任务归档

> 2026-11-15 建档。此清单覆盖 V0.1–V1.0 的计划开发工作。`[ ]` 未完成、`[x]` 已完成；仅代码、文档和验收证据齐备后勾选。任务 ID 稳定，可映射 GitHub Issue。各版本继承 PG14–18、Linux、K8S 中的 PostgreSQL、B/S 架构四项约束。

## 贯穿全程的工程任务

- [ ] **C-01** 统一事件模型：事件 ID、时间窗、资产、证据节点、关系、根因候选、人工结论和恢复验证；所有告警/巡检/Trace 均可归入事件。
- [ ] **C-02** PG14–18 兼容矩阵：每版使用五个大版本执行连接、采集、SQL 兼容和升级回归；界面标记 PG14 EOL。
- [ ] **C-03** Linux/K8S 双运行环境资产模型：统一实例身份，关联 Host 或 Namespace/Workload/Pod/Node/PVC，支持映射缺失状态。
- [ ] **C-04** B/S 安全基线：浏览器控制台 + HTTP API，Linux/Linux 容器部署，TLS、会话、权限、审计、脱敏和无默认弱口令。
- [ ] **C-05** 采集能力矩阵：按版本、权限和接入模式显示可采集、不可采集、陈旧与错误；限制采集负载。
- [ ] **C-06** 可复现故障实验：单机、主从、K8S PG 和示例应用；覆盖连接、锁、SQL、WAL/磁盘、复制、OOM、PVC。
- [ ] **C-07** 质量流水线：格式/静态检查、单元与集成测试、依赖许可和安全扫描、Linux 构建；发布前性能与恢复演练。
- [ ] **C-08** 文档与发行：部署、权限、采集开销、兼容矩阵、升级/回滚、故障演练和已知限制持续维护。

## V0.1：可运行的 B/S 纳管与监控底座

- [ ] **01-01** 建立服务端、浏览器控制台、API、配置与数据目录；可在 Linux 本机和 Linux 容器运行，健康检查可用。
- [ ] **01-02** 建立资产与只读凭据存储；支持新增/编辑/删除 PG 连接，凭据加密且不会返回给浏览器。
- [ ] **01-03** 对 PG14–18 验证连接、识别版本/角色/权限，拒绝不支持版本并对 PG14 显示 EOL。
- [ ] **01-04** 实现基础采集：可用性、连接、事务、数据库容量、主从基础状态；持久化样本与采集错误。
- [ ] **01-05** 建立 Linux/K8S 运行位置字段；K8S 实例记录 namespace/workload/pod/node 信息，未关联时显示未知。
- [ ] **01-06** 浏览器展示资产清单、实例详情、最近样本、数据新鲜度与采集状态；无 AI 环境完整可用。
- [ ] **01-07** 初始事件与证据 API：采集失败或不可用生成事件 ID，证据可追溯到资产、时间与采集错误。
- [ ] **01-08** 验收：五个 PG 大版本、Linux PG 与 K8S PG 连通性样例；服务重启后资产/样本/事件仍在，断连不误报正常。

## V0.2：PG、Linux 与 K8S 纵深观测

- [ ] **02-01** PG 会话、等待、锁链、长事务、WAL/检查点、autovacuum、表/索引容量采集，按 PG14–18 差异适配。
- [ ] **02-02** Linux CPU/内存/磁盘/IO/网络采集器，标记权限与开销，不在目标主机执行任意用户脚本。
- [ ] **02-03** K8S 只读凭据、Namespace/Pod/Container/Node/PV/PVC/Service 发现，按 OwnerReference 和标签关联 PG 实例。
- [ ] **02-04** 接入 K8S Pod 重启、状态、驱逐、OOMKilled、调度、探针、Node 压力、PVC 用量和事件；区分 API/metrics-server/exporter 来源。
- [ ] **02-05** PgBouncer 可选适配与 Linux/K8S 资源趋势联动；不可用信号显式标记。
- [ ] **02-06** 验收：从 PG 实例跳转到其 Linux 主机或 K8S Pod/Node/PVC，模拟锁等待、Pod 重启与采集权限缺失。

## V0.3：跨层告警与值班

- [ ] **03-01** 规则表达式、持续时间、严重度、去重键与版本管理；提供 PG14–18 默认规则包。
- [ ] **03-02** PG 不可用、连接、复制、锁、WAL/磁盘，Linux 资源与 K8S Pod/OOM/PVC/Node 告警。
- [ ] **03-03** 同一故障的多条告警关联一个事件 ID；时间线保留触发、确认、抑制、恢复和证据。
- [ ] **03-04** 静默、维护窗、通知路由与升级；至少一个通用 Webhook 和邮件通道。
- [ ] **03-05** 采集器失联、数据陈旧与权限变化作为独立状态告警，禁止用缺失数据得出“健康”结论。
- [ ] **03-06** 验收：PG 故障与 K8S Pod 重启同时发生时，按资产和时间窗形成可审查事件，不错误合并无关问题。

## V0.4：巡检与可恢复性

- [ ] **04-01** 巡检模板版本、规则执行、计划调度、手动执行、历史差异与失败重试。
- [ ] **04-02** PG14–18 参数/权限/冻结/复制槽/HA 检查；SQL 采集只读且有超时与开销限额。
- [ ] **04-03** Linux 系统资源、文件系统与权限检查；K8S 工作负载、探针、Pod、PVC、事件检查。
- [ ] **04-04** 备份适配器与备份年龄/失败检查，区分“未接入备份系统”和“备份正常”。
- [ ] **04-05** 容量增长与保守趋势预测，报告输出 Markdown/HTML 并关联资产、事件和原始证据。
- [ ] **04-06** 验收：复制槽膨胀、备份失败、PVC 压力和 PG14 EOL 均产生正确巡检结果。

## V0.5：SQL 性能洞察

- [ ] **05-01** 检测 `pg_stat_statements` 可用性与权限；兼容 PG14–18 字段差异，未启用时优雅降级。
- [ ] **05-02** SQL 指纹与指标聚合：调用、总耗时、平均/可用分位、读写、临时文件、趋势；避免高基数爆炸。
- [ ] **05-03** 慢 SQL 日志导入与脱敏，关联实例、时间窗和指纹；限制语句正文展示权限。
- [ ] **05-04** 执行计划采集采用显式触发或已有日志，不在生产库上自动运行高风险 `EXPLAIN ANALYZE`。
- [ ] **05-05** Top SQL、退化对比与事件证据链接；可看到 SQL 变化与 Linux/K8S 资源变化的时间关系。
- [ ] **05-06** 验收：五个 PG 大版本的可用视图测试、SQL 退化演练和无扩展降级测试。

## V0.6：一个问题的跨层根因分析

- [ ] **06-01** 证据图存储与查询：事件 → 告警 → 指标/日志/SQL/等待/锁 → Linux/K8S 资源/变更；保留时间与来源。
- [ ] **06-02** 锁阻塞链、会话/等待聚合、主从与 WAL 关联；所有节点可返回原始数据链接。
- [ ] **06-03** 确定性根因规则：连接耗尽、锁链、慢 SQL/计划变化、复制延迟、磁盘/WAL、autovacuum。
- [ ] **06-04** K8S 根因规则：Pod OOMKilled/重启、PVC 压力、Node 资源/调度异常与 PG 服务退化的时间关联。
- [ ] **06-05** 根因候选展示匹配条件、证据、反证、时间顺序、置信级别和缺失信号；支持人工确认/驳回。
- [ ] **06-06** 验收：八类故障演练中，从同一事件页能追踪问题全程；无法证实时返回“未定位”而非编造结论。

## V0.7：应用到数据库的全链路定位

- [ ] **07-01** 接入 OTel 数据库客户端 Span 和服务身份，遵循 PostgreSQL 语义约定并控制 SQL 敏感字段。
- [ ] **07-02** 连接服务/请求/Trace/连接池/PG 实例/SQL 指纹/Host 或 Pod/Node/PVC 的身份映射与时间关联。
- [ ] **07-03** 事件页提供双向下钻：慢请求 → SQL/PG/基础设施，以及数据库故障 → 受影响服务和请求。
- [ ] **07-04** 标示链路断点、采样率与时钟偏移；没有应用 Trace 时保持数据库侧诊断可用。
- [ ] **07-05** 影响面计算与依赖拓扑，按资产权限控制可见服务和 Trace。
- [ ] **07-06** 验收场景 A：应用慢请求 → DB Span → SQL 锁等待 → 阻塞会话 → 根因候选；场景 B：应用连接失败 → PG Pod OOMKilled/重启 → K8S 事件和资源证据 → 根因候选。每个场景都必须在**一个事件 ID** 下完成回溯。

## V0.8：可选 AI 分析与预警

- [ ] **08-01** 可配置本地模型与兼容 API，模型未配置、失败、超时或预算耗尽时不影响核心功能。
- [ ] **08-02** 按用户权限生成脱敏事件证据包，支持关闭外发、保留期与模型调用审计。
- [ ] **08-03** AI 摘要、问答和预警建议引用证据 ID，标注不确定性，不生成不可核验的“确定根因”。
- [ ] **08-04** 无模型容量/趋势规则预警与 AI 建议并存，避免 AI 成为唯一预警来源。
- [ ] **08-05** 验收：断开模型后完成 PG/Linux/K8S 的监控、告警、全链路定位、规则根因分析和事件报告。

## V0.9：运维治理与协同

- [ ] **09-01** 组织/资产范围 RBAC、浏览器会话保护、API 权限覆盖与租户数据隔离。
- [ ] **09-02** 工单、值班负责人、审批流、维护窗与变更记录关联事件。
- [ ] **09-03** 受控低风险操作的预演、授权、审批、执行回执、超时和审计；高风险动作保持人工执行。
- [ ] **09-04** 凭据轮换、K8S ServiceAccount 最小只读权限、密钥加密与审计日志防篡改策略。
- [ ] **09-05** 事件复盘报告：时间线、影响、证据、根因候选、人工结论、处置与恢复验证。
- [ ] **09-06** 验收：只读账号无法执行任何变更；审批前不能执行受控动作；审计可从事件追溯到操作人。

- [ ] **10-01** PG14–18 × Linux 裸机/虚机/K8S × 单机/主从/Patroni/至少一种云 PG 的支持矩阵和回归结果。
- [ ] **10-02** B/S 控制台可访问性、中文与英文基础文案、性能与大规模资产分页/保留期测试。

- [ ] **10-07** 无 AI 模型的完整回归、模型可选模式回归、已知限制和 PG14 EOL 文案发布。

## 发布规则

完成一个版本须勾选该版所有任务，并有代码/文档/自动化或人工验收记录。后续版本可提前开发，但不得用“规划完成”代替功能实现。任何对功能、兼容性或安全边界的变更都需同步更新此清单和[路线图](ROADMAP.md)。
