# V0.3 PostgreSQL 18 长期监控存储（开发中）

正式模式继续使用与被纳管业务库隔离的 PostgreSQL 18。V0.3 开发代码把采样和事件表改为按 UTC 月份的 RANGE 分区，启动时预建当前与下一月分区，跨月写入前也会创建所需分区。事件 ID 保留在独立身份表中，证据和通知仍通过同一个事件 ID 关联。已有 V0.2 普通 `samples` 与 `events` 表会在启动事务内搬迁到月分区；迁移期间需要数据库写锁，建议先备份 PG18、安排停写窗口，并核对样本、事件与证据数。SQLite 导入 PG18 时按源数据月份建分区。

控制台展示监控库占用、采样/事件分区占用、采样/事件数、最早时间和近七天的日均采样数，并按当前平均样本占用粗估每日增长。资产页可按小时聚合近 24 小时的采样次数、失败次数和平均连接数；API 可在最多 90 天范围内按 1–24 小时桶查询。增长估计包含分区索引占用，只用于容量预估，不保证未来负载不变。

默认不自动删除历史数据。如需采样保留期，在 `.env` 中设置 `DBSPHERE_RETENTION_DAYS=90` 等 1–3650 的整数；如需已结事件保留期，另设 `DBSPHERE_EVENT_RETENTION_DAYS=180`。重新运行一键部署脚本后，每日最多清理 10000 条超期采样和 1000 个已结事件。仍被**未结事件**证据引用的采样不删；待投递或最终失败、尚可手动重试的通知会阻止对应已结事件删除。未结事件永不按保留期删除。清理前应做好 PG18 备份。分区批量卸载、正式规模升级与备份恢复演练仍待实现，因此 V0.3 尚未发布。
