# V0.3 PostgreSQL 18 长期监控存储

正式模式继续使用与被纳管业务库隔离的 PostgreSQL 18。V0.3 把采样和事件表改为按 UTC 月份的 RANGE 分区，启动时预建当前与下一月分区，跨月写入前也会创建所需分区。事件 ID 保留在独立身份表中，证据和通知仍通过同一个事件 ID 关联。已有 V0.2 普通 `samples` 与 `events` 表会在启动事务内搬迁到月分区；迁移期间需要数据库写锁，建议先备份 PG18、安排停写窗口，并核对样本、事件与证据数。SQLite 导入 PG18 时按源数据月份建分区。

控制台展示监控库占用、采样/事件分区占用、采样/事件数、最早时间和近七天的日均采样数，并按当前平均样本占用粗估每日增长。资产页可按小时聚合近 24 小时的采样次数、失败次数和平均连接数；API 可在最多 90 天范围内按 1–24 小时桶查询。增长估计包含分区索引占用，只用于容量预估，不保证未来负载不变。

默认不自动删除历史数据。如需采样保留期，在 `.env` 中设置 `DBSPHERE_RETENTION_DAYS=90` 等 1–3650 的整数；如需已结事件保留期，另设 `DBSPHERE_EVENT_RETENTION_DAYS=180`。重新运行一键部署脚本后，每日最多清理 10000 条超期采样和 1000 个已结事件。仍被**未结事件**证据引用的采样不删；待投递或最终失败、尚可手动重试的通知会阻止对应已结事件删除。未结事件永不按保留期删除。清理前应做好 PG18 备份。分区批量卸载、正式规模升级与备份恢复演练仍待后续版本。

## Go 开发版的长期分区维护

Go/PG18 架构在启动迁移时创建采样和事件的当月及未来两个月 UTC 分区，并在服务运行期间每小时检查和预建；即使自动采集关闭，分区维护也运行。多个 Go 副本使用与 schema 迁移相同的 PostgreSQL advisory transaction lock，避免同时建表；如果同名表存在但未挂到正确父表，维护返回错误并记录日志。独立 PG18 实库测试把时间推进三个月，重复维护两次后确认两类分区均已挂载，实际未来采样和事件写入分别落到对应月分区。[31 项 Linux CI](https://github.com/cuipengdba/DbSphere/actions/runs/44394389901)通过，单节点 kind 滚动更新后的数据读回见[本机记录](KIND_ACCEPTANCE.md)。

Go 版现支持可选的 `DBSPHERE_RETENTION_DAYS`（样本）与 `DBSPHERE_EVENT_RETENTION_DAYS`（已结事件），均须为 1–3650 的整数。默认均为空，即不自动删除。可在 `deploy/compose/.env.go` 或离线包的 `dbsphere-go.env` 中设置；服务启动后立即执行一次，此后每小时追赶过期数据。每类数据单轮最多 100 批，样本每批 10000 条、已结事件每批 1000 个，批间隔 100 毫秒，单类最长运行 2 分钟；未清完的积压留到下一个小时。清理数量和可能积压写入服务日志，控制台展示实际配置的保留天数。[容量初测](RETENTION_CAPACITY.md)记录了本机 120000 条样本和 5000 个事件的追赶结果及限制。

样本清理保留仍被任意事件证据（含嵌套的 `sampleId`、`baselineSampleId` 等）或巡检历史引用的样本。Go schema 版本 21 为证据中的样本 ID 建立独立引用表与索引：迁移时回填既有证据，之后由 PostgreSQL 触发器跟踪新增及修改的证据；删除事件时外键级联移除对应引用。样本时间、已结事件时间和巡检引用也有清理专用索引，使日常清理不必遍历全部证据。既有证据较多的环境应在备份后安排维护窗口执行首次回填，并观测迁移耗时与 PG18 空间占用。

事件清理只处理超过期限的已结事件；未结事件、仍在活动分组中的事件、有待投递/失败通知的事件，以及巡检报告关联的事件均保留。事件及其证据按外键级联删除后，才清理不再被引用的样本。这个安全优先规则意味着实际存储时间可能超过配置值；应先做 PG18 备份，再开启自动清理。真实 PG18 集成测试覆盖批量上限、嵌套证据、证据修改、巡检、通知和未结事件保护；本机完整 Go 测试已通过。

新索引消除了日常全表证据扫描。启用相应保留期后，每日清理会在逐行删除后尝试移除最多 4 个**完全早于保留时间且已无存活数据**的旧 UTC 月分区；先核对分区名称和范围，取得父表及子表锁后再次确认分区为空。仍有证据或巡检保护的数据会使整个分区留存，未启用事件保留期时不清理事件分区。此操作会短暂锁定相应分区父表，必须通过生产负载验收。[本机 kind 现有库迁移](KIND_ACCEPTANCE.md#2026-11-19-证据引用索引迁移)及[33 项 Linux CI](https://github.com/cuipengdba/DbSphere/actions/runs/44403758760)验证小规模回填与 Go 包升级回滚；[空分区清理的 33 项 CI](https://github.com/cuipengdba/DbSphere/actions/runs/44406742952)和[本机运行复验](KIND_ACCEPTANCE.md#2026-11-19-保留期与空分区运行复验)通过。大数据量删除、迁移回填、索引体积和分区清理锁耗时仍未完成容量基线和生产规模验收。正式版的备份恢复、PG18 数据库升级和生产存储故障演练仍是 V1.0 门槛。
