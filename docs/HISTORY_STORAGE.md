# PostgreSQL 历史指标分层

管理员可在 **系统 → 指标保留** 按组织配置连接数、复制延迟、数据库容量和 Linux CPU 使用率的存储周期。原始值保留 1–90 天，小时汇总周期至少与原始周期相同，最长 365 天。已有部署通过 PG18 迁移启用界面。保存策略后，维护副本按批推进归档时点。

在资产详情展开 **分层历史趋势**，选择指标和 7、30 或 90 天时间窗。每个小时可以查看均值、最大值、有效采样数，以及原始、归档或两者混合的来源。图表用左右方向键查看时间点，或拖拽缩小时间窗。无可用样本的区间留空。

归档按完整 UTC 小时处理。过期指标原始值与小时统计在同一事务中转换，重试沿用已入库的样本和累计统计。事件与巡检引用的原始样本持续可回查。受保护的原始值和已归档的统计在查询时合并计数。提高原始值保留天数影响后续保留，已经归档的小时仍按小时统计读取。

`GET /api/assets/{id}/history-tier` 接受 `metric`、`from`、`to`。起止时间以整小时对齐，查询最长 90 天，通过资产权限验证。管理接口是 `GET|PUT /api/admin/history-retention`，更新策略由现有组织审计记录。

策略、小时汇总和原始引用都保存在长期 PG18 中，沿用现有备份和恢复流程。容量验收使用仓库的 **PostgreSQL history capacity** 工作流，以 300 个实例、90 天和每 5 分钟一个样本生成 7,776,000 条记录。测试使用五并发读取、原始采集写入和隔离恢复，输出缓存清理范围、冷暖查询 P95、写入计时、备份大小和恢复计数。
