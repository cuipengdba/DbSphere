# 数据库变更治理

在「资产与实例」打开 PostgreSQL 或 MySQL 资产，展开「数据库变更治理」。管理员可以创建仅适用于当前资产的窗口，也可以将窗口应用到该资产所在组织。开始和结束时间按浏览器本地时区输入，服务器以 UTC 保存，最长七天。窗口用于变更审批和回执核验，告警规则仍随采样运行。

| 操作 | 执行者 | 留存记录 |
| --- | --- | --- |
| 创建窗口 | 组织或平台管理员 | 范围、开始和结束时间、创建人 |
| 提交变更申请 | 资产管理员或已授权运维人员 | 窗口、变更目的、组织内唯一外部单号、申请人 |
| 批准或驳回 | 具备资产权限的独立审批账号 | 审批人、决定、时间 |
| 执行只读预检 | 资产管理员或已授权运维人员 | 原始样本、连接数、锁等待、未关闭事件和 SQL 统计覆盖 |
| 上线复核与回退核对 | 资产管理员或已授权运维人员 | 核对人、结果、原始样本、关联事件 |

批准后、外部执行前再取一次基线。开始回执要求服务器当前时间位于窗口内，且该基线为目标的最新成功样本，距当前时间最多 15 分钟。自动采集更新样本后，可重新点「执行只读预检」。数据库连接配置变化后，应重新提交变更。跨会话统计权限不足时显示缺采。阻塞为零、连接数可见且采集会话为只读时，预检显示「当前检查通过」。

## 通用 ITSM 接入

为外部执行流程配置组织范围的运维 API 令牌和可信 HTTPS 入口。ITSM 根据自身审批和执行约束管理变更任务，并在每个阶段通过 `POST /api/v1/change-receipts` 回传状态。使用页面显示的变更 ID 和申请时登记的外部单号。可将仓库中的参考脚本放在执行器上，依赖 Bash、curl 和 jq。 [参考脚本](../scripts/submit-change-receipt.sh) · [运维 API 配置](OPERATIONS_INTEGRATION.md)

```bash
export DBSPHERE_API_ORIGIN=https://dbsphere.example.org
# 由执行器密钥管理向脚本提供 DBSPHERE_OPS_TOKEN。
bash submit-change-receipt.sh "$CHANGE_ID" "$TICKET_ID" "$DELIVERY_ID" started
```

`started` 通过后，外部执行器才开始验证过的数据库变更步骤。执行结束发送 `succeeded` 或 `failed`，执行回退后发送 `rolled_back`。每阶段生成独立回执 ID，同一阶段重试沿用原 ID 及原内容。首次保存返回 201，重复保存返回 200 和 `duplicate: true`。时间窗、变更状态、外部单号或回执内容有冲突时返回 409，外组织变更单返回 404。执行及回退由外部执行器完成。

## 上线与回退核对

刷新变更记录，在变更单中对照上线前后的连接、锁等待和告警证据。已关联的事件保留外部回执，事件时间线中的原始采样链接可返回同一事件。变更窗口内的同资产事件可供人工核对，事件同窗表示时间关联。需要核查同一 SQL 指纹时，在关联事件的「SQL 性能对比与复测」选取上线前后两个窗口。回退后点击「保存回退核对」生成新样本并记录人工确认。 [SQL 性能对比与复测](SQL_PERFORMANCE_COMPARISON.md)
