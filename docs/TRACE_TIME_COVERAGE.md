# 应用 Trace 采样声明与时间可信度

V1.0.7 在同一事件 ID 的应用链路区显示采样**声明**和时间异常，不将已收到的 Span 数量外推为请求覆盖率，也不把时间差当成已测得的时钟偏移。

## 接入字段

应用或 Collector 可在 OTLP/HTTP JSON 的 Resource 属性中设置 `dbsphere.trace.sampling_probability`。值为 `doubleValue` 或十进制 `stringValue`，范围是 `0 < p <= 1`；例如 `0.25` 表示发送方声明的 25% 采样概率。无效值忽略，未声明时显示“未知”。该字段仅随严格匹配到唯一受管 PG 资产的脱敏 Span 保存，SQL 正文、URL、参数和任意其他属性仍不入库。

```json
{"key":"dbsphere.trace.sampling_probability","value":{"doubleValue":0.25}}
```

事件页和复盘报告展示当前事件窗口内最多 100 条 Span 的声明数量与概率范围。即使所有 Span 都声明同一概率，这也不是实际请求量、Trace 完整率或丢包率的测量值；各服务和不同采样策略可能给出不同值。影响面仍只按可核对的已观测 Trace 计数。

## 接收时间与根因判断

Go 服务收到 OTLP 请求时为每个允许的 Span 记录入口接收时间。分批先到的服务父 Span 在 PG18 待关联表保留原入口时间；十分钟补链有效期继续使用 PG18 自身的存储时间，避免 Go 与 PG18 时钟不一致时提前清理。已有旧 Span 的入口时间为空，显示为未核对。

如果 Span 的结束时间晚于 DbSphere 入口接收时间超过一秒，事件图保留该 Span 和脱敏原始链接，但将其时间关系标为“待核对”。此 Span 不用于锁等待根因候选、Query ID 同窗指纹匹配或服务故障影响面的跨层时间关联；事件页和报告显示异常条数与最大表观超前量。应用主机、Collector 与 DbSphere 的时钟或上报时间戳都需要排查。没有观察到未来时间戳也**不能证明**时钟同步；网络排队和延迟使反向偏差无法从接收时间单独求出。

本机 PG18 集成测试覆盖 schema 30/31 升级、有效与无效采样声明、原始 Trace 脱敏、异常 Span 的事件关系和影响面抑制，以及分批父 Span 的入口时间与 PG18 缓存时间分离。生产多语言 SDK 的属性注入、真实采样覆盖率和端到端时钟偏移测量仍待验收。

## v3.17.0 请求与基础设施证据

在「事件 → 根因候选 → 数据库请求路径」展开 PostgreSQL 调用。逐段核对 Span ID、父 Span ID、开始时间、接收时间状态以及后端等待 PID。缺失父 Span、时间不重合和循环分别提示。事件图和上游服务影响面同时排除时间冲突的关系。

已映射到 Kubernetes 数据库资产的请求可通过该资产配置的只读 Kubernetes 上下文核对应用 Pod UID。应用 PVC 的 UID 来自命名空间查询。PV UID 需要 `get persistentvolumes` 权限，并核对绑定的 `claimRef`。容器 ID 和卷状态是 Kubernetes API 观测时的快照。相同工作负载按集群、命名空间和名称比较相邻 API 快照，提示同名对象 UID 变化。

主机、数据库 Pod、容器、卷和连接池的读数按来源时间筛选。缺少来源时间的旧样本使用采集时间。同窗采样用于排查，匹配 Pod UID、容器 ID 或 PVC UID 的证据单独标示。点击原始采样后可从采样页返回同一事件。原始 Trace 在新标签页打开。
