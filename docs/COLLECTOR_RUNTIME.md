# 采集健康与调度

Go 服务在「系统状态 → 自动采集运行状态」向管理员显示当前进程的采集循环。`GET /api/admin/collector` 需管理员会话。关闭自动采集时显示「已关闭」。

当前运行轮次的开始时间与最近**已完成**轮次的开始、结束、耗时、选中和实际处理的资产数分开显示。另记录目标采集失败数、采集器执行错误数、待采集资产扫描是否失败，以及是否碰到每轮 100 个资产的选择上限。目标采集失败是 `CheckAsset` 成功保存了 `status=error` 的目标样本；执行错误是采集器未能完成资产检查或陈旧告警评估，需查服务日志和 PG18 连接。碰到上限只说明本轮选满，**不能据此计算实际积压**。

状态区分等待首轮、运行中、正常、最近一轮错误、运行超出两个周期和循环未按周期推进。长批次仍在执行时显示“超出周期”，不会误称已经停止；批次完成后从完成时间计算下一轮是否停滞。该视图只反映当前 Go 进程，重启后轮次计数清零；历史资产样本与告警仍保存在 PostgreSQL 18。它不代替外部存活探测、故障通知或多副本采集租约。

「查看采集覆盖与耗时」按组织、引擎和部署环境显示近期成功、逾期、隔离、退避、目标失败、执行错误和权限受限。P95 采用各实例最近一次调度的有效耗时。PG18 写入事务耗时包含样本、事件及证据写入，测量截止于任务状态更新前。权限缺口按适配器实际回报，旧采样和无权限报告的任务显示为未核对。

常规队列按引擎交错领取到期任务。引擎内按到期时间排序。自动退避和隔离沿用共享租约，失效副本无法提交同一租约的重复样本。增强包可使用 `dbsphere_collector_queue_seconds`、`dbsphere_collector_query_seconds`、`dbsphere_collector_store_seconds`、`dbsphere_collector_permission_gaps`、`dbsphere_collector_isolated` 和 `dbsphere_collector_backoff`。 [混合负载复测](COLLECTOR_LOAD_ACCEPTANCE.md)
