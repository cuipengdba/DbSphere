# 自动采集进程状态

V1.0.8 的 Go 服务在“系统状态 → 自动采集运行状态”向管理员显示当前进程的采集循环。`GET /api/admin/collector` 需管理员会话；未登录和只读查看账号不能读取全平台采集统计。关闭自动采集时显示“已关闭”，不将其误报为停滞。

当前运行轮次的开始时间与最近**已完成**轮次的开始、结束、耗时、选中和实际处理的资产数分开显示。另记录目标采集失败数、采集器执行错误数、待采集资产扫描是否失败，以及是否碰到每轮 100 个资产的选择上限。目标采集失败是 `CheckAsset` 成功保存了 `status=error` 的目标样本；执行错误是采集器未能完成资产检查或陈旧告警评估，需查服务日志和 PG18 连接。碰到上限只说明本轮选满，**不能据此计算实际积压**。

状态区分等待首轮、运行中、正常、最近一轮错误、运行超出两个周期和循环未按周期推进。长批次仍在执行时显示“超出周期”，不会误称已经停止；批次完成后从完成时间计算下一轮是否停滞。该视图只反映当前 Go 进程，重启后轮次计数清零；历史资产样本与告警仍保存在 PostgreSQL 18。它不代替外部存活探测、故障通知或多副本采集租约。

本机回归覆盖长批次完成后的状态、停滞/关闭区别、目标失败与执行错误分账，以及管理员/只读账号的接口权限。完整 PG14–18、Kubernetes、离线包和故障演练由本版 CI 验证。持续负载下的采集开销、资产积压深度、进程意外退出后的外部告警与高可用控制台仍未验收，因此原计划任务 10-04 保持未完成。
