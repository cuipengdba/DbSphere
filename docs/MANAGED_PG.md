# 托管 PostgreSQL 纳管模式

> 开发版功能。此模式已用本地 PostgreSQL 18 监控库与 PostgreSQL 14 目标验证，并纳入 PostgreSQL 14–18 的 CI 目标矩阵；尚未在任何云厂商的实际托管实例上验收，不能据此宣称某个服务已受支持。

在 B/S 控制台选择“托管 PostgreSQL”，填写主机、端口、数据库、只读监控用户和 TLS 模式。DbSphere 从独立的 PostgreSQL 18 监控库调度采集；目标实例只通过 PostgreSQL 协议接受只读连接。数据库服务可位于云上或其他无法读取主机/Kubernetes API 的环境。

| 信号 | 托管模式当前能力 | 边界 |
| --- | --- | --- |
| PostgreSQL 版本、主备角色、连接、事务、容量 | 采集 | 需要目标允许连接和查询；支持版本限定 14–18 |
| 锁链、等待、复制、WAL、autovacuum、Top SQL | 尽力采集并显示各信号状态 | 取决于监控账号权限、服务端视图与云服务限制；缺失保持“未采集/未知” |
| 告警、同事件 ID 证据、规则根因候选、复盘报告 | 使用实际获得的数据库证据 | 不从数据库侧推断未提供的应用请求或宿主机故障 |
| 应用 Trace、慢 SQL 日志、执行计划 | 可通过现有独立接入/导入路径关联 | 需要应用埋点或日志/计划来源；数据库连接本身不提供完整调用链 |
| Linux 主机、node_exporter、K8S Pod/Node/PVC/Event | 不采集 | 资产详情明确标为不可用，不生成虚构基础设施节点或正常状态 |
| PgBouncer、Patroni | 可分别配置只读端点 | 取决于托管服务是否暴露相应端点；未配置时不声称可用 |

“验证服务器证书”TLS 选项由 Go 采集器使用 `verify-full`，同时验证证书链和主机名；关闭 TLS 仅适用于受信测试网络。实际云验收需要核对厂商 CA、DNS、只读角色允许的视图、连接数限制及告警误报。当前本地夹具使用关闭 TLS 的回归路径，不能替代该验收。
