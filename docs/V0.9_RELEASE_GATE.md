# V0.9.0 事件工单与受控只读采样发布验收

> 2026-11-19。本版交付可审计的双角色审批闭环；尚未实现组织级多用户或跨租户权限，不能以此版本宣称企业级完整 RBAC。

## 发布范围

- 事件页新增工单。管理员只可为开放事件申请一次只读采样，填写 5–300 字原因；页面显示预演说明、目标资产、15 分钟到期时间和当前状态。每个事件同时最多 3 个有效申请。
- 可选 `DBSPHERE_APPROVER_PASSWORD` 启用独立审批账号。密码须不少于 12 字符并区别于管理员和只读账号；其会话使用独立签名密钥，轮换或移除密码后旧会话失效。审批账号只能批准或驳回工单，不能新增资产、直接执行动作或修改监控配置。管理员不能批准自己的工单。
- 批准后，管理员可在有效期内执行该工单一次。服务端原子消耗审批状态，并对绑定的资产执行一次既有只读采集；在目标上不执行 SQL 变更或 Kubernetes 写操作。事件关闭、审批拒绝、超时或重复执行均被拒绝。采样最长 35 秒，结果样本 ID、状态及两种账号的请求结果写入原事件 ID 的证据和操作审计。
- 沿用 PostgreSQL 14–18、Linux/Kubernetes 纳管、应用到数据库证据链、可选 AI、Go 静态服务端、静态 B/S 页面、独立 PostgreSQL 18 存储和 Linux x86_64 一键离线容器包。

## 已知限制与后续任务

V0.9.0 提供管理员、只读查看与独立审批三种全局角色，以及单一只读账号的资产白名单；尚无个人账号、组织/租户隔离、值班负责人分派、外部工单系统、变更单或维护窗与工单的直接关联。当前审批动作是一次只读采样，旧有管理员手动采样仍可直接使用；审批不代表对所有采集操作加锁。审计以账号角色标记，尚不能证明实际自然人身份或防数据库管理员篡改。进程在工单执行中被强制终止时，工单可能停留在“执行中”，需要管理员核对目标样本；自动恢复租约尚未实现。上述限制列在[开发任务清单](DEVELOPMENT_TASKS.md)继续处理。
