# DbSphere v2.15–v2.19 数据库日志分析规划

在 DbSphere 内增加「日志分析」工作台。用户按项目、环境和数据库实例上传日志，先看本批次的异常和应用负载，再与历史基线比较，最后沿同一个事件查看根因、原始记录和调优效果。界面沿用 DbSphere 的深浅主题，默认深色。顶部固定项目、实例、批次和时间窗，报告中的应用、SQL 指纹和事件可以相互下钻。

## v2.15.0 日志导入与多项目管理

- [ ] 建立项目、环境、实例、分析批次和来源文件的关系。平台组织负责权限范围，项目可关联多个已纳管实例，也能登记仅用于离线导入的实例。批次列表展示时间范围、日志类型、记录量、异常数和解析状态。
- [ ] 在现有资产级慢日志导入基础上，建设 Go 流式上传、后台解析和增量提交。首批覆盖标准 PostgreSQL 14–19 与已纳管的瀚高安全版 4.5.9。PostgreSQL 目标格式涵盖文本前缀、CSV 和有原生支持版本的 JSON，瀚高按实测文本及 CSV 布局验收。
- [ ] 支持选择多个轮转文件，自动识别格式和常见前缀并提供预览。识别结果给出依据和覆盖率，无法判定时由用户选择产品、格式、时区或填写前缀。导入状态包含成功、部分解析和失败，并能定位未识别记录。
- [ ] 从首版采用独立 Zstd 压缩分块保存原始记录。PostgreSQL 18 保存来源映射、批次元数据、标准化事件和聚合索引。按来源文件摘要、节点和记录身份去重，重复导入能找到原批次。
- [ ] **验收**　两个项目及多个实例可以同时分析。同一轮转文件重复上传保持计数一致。覆盖多行 SQL、不同前缀、错误文件和时区切换，授权用户从一条慢 SQL 或错误记录可打开原始上下文。

## v2.16.0 金仓 V9、达梦 DM8 日志适配与全景分析

- [ ] **人大金仓 KingbaseES V9**　适配 CSV 日志和带 `log_line_prefix` 的文本日志，验收会话、应用名、SQLSTATE、SQL 耗时及锁与错误记录的提取。兼容矩阵列明通过真实样例验证的 V9 小版本和日志格式。 [KingbaseES V9 日志说明](https://help.kingbase.com.cn/v9.3.11/admin/reference/ref-database-parameter/initialization-parameters/runtime-config-logging.html)
- [ ] **达梦 DM8**　实现独立解析器，适配 `dmsql_*.log` SQL 跟踪日志及相关运行日志。根据实际日志模式提取会话、SQL、耗时和错误，校验时间单位，按达梦方言归一化 SQL 指纹。保留原始错误码及记录位置，将锁和死锁关联到可验证的会话证据。 [达梦跟踪日志说明](https://eco.dameng.com/document/dm/zh-cn/ops/performance-diagnosis) · [DM8 日志模式](https://eco.dameng.com/document/dm/zh-cn/pm/physical-storage.html)
- [ ] 增加全景报告，覆盖读写 SQL 速率、事务速率、P95/P99、Top 慢 SQL、错误、锁等待、死锁、Checkpoint 刷脏、Autovacuum 和临时文件。按引擎和实际日志能力呈现专题，例如将 Autovacuum 展示在具备该信号的引擎上。指标可定位到分钟、实例、数据库、应用、SQL 指纹及原始记录。 [pgBadger 报告与日志配置](https://github.com/darold/pgbadger)
- [ ] 建立 Application 流量与资源矩阵。每行显示应用的已记录语句数、累计 SQL 耗时、P95、锁等待时间、临时文件量及错误数。点击热点进入相关 SQL 或事件。已采集的应用 Trace 可关联到请求入口，主机 CPU 和磁盘 I/O 按各自数据来源展示。
- [ ] 将全量统计、采样统计、慢日志观测量分开呈现。只有完整明细或可核对同期监控计数时才展示全量 QPS/TPS。P95/P99 显示样本量和覆盖。应用维度取自日志中的应用标识或经验证的关联信息，其余归入「未标识」。 [PostgreSQL 记录与采样说明](https://www.postgresql.org/docs/19/runtime-config-logging.html)
- [ ] **验收**　用金仓 V9 和 DM8 的真实日志分别核对格式识别、慢 SQL 耗时、错误计数、SQL 指纹和原始记录回溯，同时复测 PostgreSQL 与瀚高的导入。用具备应用字段的样例验证矩阵归属，用具备阻塞关系的样例验证等待者到阻塞者的证据链。分别用带耗时和仅记录语句的 DM8 样例核对图表覆盖情况。

## v2.17.0 跨批次优化对比

- [ ] 将截图中的对比页作为此版本的主界面。顶部并排选择基线与当前批次，展示两段时间、覆盖及健康分差。中部用三张卡展示「慢 SQL 优化」「锁与死锁变化」「回退与新增风险」。下方为逐项对比表，按已解决、明显改善、性能劣化、新增问题筛选。
- [ ] 以带算法版本的归一化 SQL 指纹对齐批次。锁问题和异常错误另外按对象、锁类型、SQLSTATE 等稳定字段对齐。并排提供频次、每小时频次、累计耗时、P95、受影响应用和原始证据。相同 SQL 在不同 schema、租户或不可验证的实例间保持正确归属。
- [ ] 对齐工作时段、日志阈值、实例角色和样本量。能够复核问题在可比负载下消失时标记「已解决」。只有阈值截断后的慢日志且未观察到问题时，显示「本批次未检出」及覆盖情况。评分公开扣分规则和口径版本，数据覆盖不足时单独提示。
- [ ] 增加项目健康视图，汇总各项目最新可评估批次的健康评分、评分趋势、已处理问题和新增风险。点击某个得分或趋势点回到对应项目、实例和批次。
- [ ] **验收**　用一组包含慢 SQL 改善、锁等待下降、死锁变化、回归和新增错误的基线与复测日志，逐项核对分类。相同日志重复对比结果一致。日志阈值改变、时区不同或样本过少的案例均能解释比较限制。点击任一变化可查看两个批次的样本和对应事件。

## v2.18.0 同一事件的根因分析与 AI 调优

- [ ] 复用 DbSphere 事件调查，以已有事件 ID 关联日志、等待、SQL 指纹、计划、应用、主机容器指标及变更记录。无已有事件时可建立调查事件，并把后续分析和复测结果挂到该事件。展示直接证据、时间相关性、根因候选和缺失信息。
- [ ] 先交付基于规则与可验证证据的摘要和 P0–P3 优先级。默认 P0 代表紧急且高影响的故障，P1 代表需优先处置的回退或持续异常，P2 代表可安排验证的优化，P3 代表继续观察的线索。显示评级依据，项目、应用和实例范围贯穿整个调查。
- [ ] 接入可选 AI Agent，支持围绕当前事件追问、比较候选原因和生成优化方案。有证据时提供面向对应数据库版本的索引 DDL、SQL 改写或参数建议。每项方案附涉及对象、预期验证指标、实施条件、潜在影响和回退办法。在线模型默认使用脱敏片段，原始日志保存在部署环境内。
- [ ] **验收**　分别用锁阻塞、慢 SQL 回归和临时文件溢出进行演练。沿大屏或批次明细进入同一个事件，可追到原始记录和验证结果。有模型时核验回答引用及对话范围，关闭模型时验证规则摘要、全景报表和原始证据均可使用。

## v2.19.0 大规模归档、增量分析与离线交付

- [ ] 完善 Zstd 分块归档和 PostgreSQL 18 聚合索引。通过记录到压缩分块的映射回看前后日志。跨批次查询优先读取已计算的统计、指纹和可合并分布，按需读取相关压缩块。
- [ ] 完善断点续传、解析重试、并发配额、热冷保留策略、索引重建、完整性校验及备份恢复。对已有分析数据和归档文件进行成套升级验收。空间视图展示真实归档用量、压缩率、保留期限及任务积压。
- [ ] 提供 Linux amd64、arm64 的标准版和增强版一键离线安装及升级。核验与既有 PostgreSQL 18 存储、Go 服务端、静态 Web 控制台和站内可观测性组件的集成。文档按实际测试范围公布数据库、版本和日志格式矩阵。
- [ ] **验收**　在记录 CPU、内存、磁盘和并发数的测试机上导入至少 10 GiB 混合日志，记录吞吐、峰值内存与实际压缩比。将 30 天范围的索引化跨批次对比 P95 ≤ 2 秒作为性能目标，单独记录原始上下文读取耗时。验证中断重试和断网升级后能按原事件及批次追溯同一条记录。

## 共同验收约定

- 每个版本分别验收日志覆盖及一键离线包。日志文件适配按实测版本发布，在线监控纳管按现有能力矩阵独立验收。
- 原始日志归档按项目权限访问并记录审计。结构化页面、报表和外部模型输入使用脱敏数据。原有轻量慢日志记录继续可查，新增原文回溯来自新归档的批次。
- 对比卡和根因页均提供原始证据入口。监控与日志关联以可信实例身份、时间窗、应用、会话、SQL 指纹或已有事件为依据，并标明关联强度。
