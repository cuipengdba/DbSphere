# 事件调查工作台

从「实时观测」异常入口或「问题事件」进入。首屏显示同一事件的症状、可见关联实例、主要候选、关键原始采样和待核对项。跨实例事件保留子事件的原始 ID、开始时间和各自的结束时间。在工作台左下角可核对正在运行的 DbSphere 版本。

在「同一时间窗」选择故障前、触发时、峰值或恢复后。应用、入口与连接池、数据库、Linux 与 Kubernetes、容器与存储使用同一时间游标。单击标记定位已观测到的证据，查看原始采样或 Trace。沿等待趋势、锁树、存储或 Grafana 专题返回时保留事件 ID、阶段和已选证据。复制当前事件地址可恢复同一选区。

对于有原始锁等待告警样本的事件，「查看阻塞者原始采样」可以核对等待 PID、阻塞 PID 和已采集的 Query ID。PgBouncer 等待和主库回放差距可打开出现信号的样本。PVC 峰值核对同名同 UID 的卷，容器 I/O PSI 核对同一容器 ID。峰值最多检查触发后的 120 条原始采样，达到上限时显示扫描截止时间。时间相关、标识冲突、缺采和人工复核状态在候选旁可见。

「下载当前证据复盘」导出事件 ID、当前链接、时间窗、关键证据、恢复样本和人工复核摘要。原始链接沿用 DbSphere 会话与资产访问范围。未配置 AI 时仍可使用采样与规则完成调查。

在监控工作台的实例概览、等待分析或 SQL 性能中，可从「性能峰值调查」选择时间桶，核对阻塞会话、连接告警信号和 SQL 耗时退化的峰值样本。告警记录引用同一资产、同一信号和同一原始样本时，提供原事件入口。同一时间桶内的峰值与触发样本不同时，页面单列触发样本及其原事件。事件阶段对照展示连接占用、等待和样本记录的退化 Query ID。锁等待事件核对触发前后十分钟内的相邻样本，使用实例端点、实例启动时间和会话启动时间辨别同一会话。权限不足、旧样本或缺采时显示可用的观测范围。

## SQL 性能对比与复测

从 PostgreSQL 或 MySQL 事件打开「SQL 性能对比与复测」。用同一指纹比较基准期和变更期，查看两端原始采样、计划差异与慢日志。在相同事件保存修复后的复测记录。证据助手可引用已保存结果。[操作手册与匹配口径](SQL_PERFORMANCE_COMPARISON.md)

## MySQL、Redis 和 etcd 专项诊断

从资产详情或实时观测的诊断区打开专项页面，按时间选择采样。页面在异常或恢复记录引用该采样时提供原事件入口。原始采样与事件页均可返回原时间窗和所选采样。

- MySQL 并列展示 InnoDB 等待关系、同期活跃事务、累计 SQL 指纹和复制通道状态。采样中的线程关系以 `performance_schema` 为依据，累计 SQL 统计保留自身口径。
- Redis 对照内存、相邻样本的淘汰与命中率和客户端 INFO 往返，并标记计数器重置、进程更换及窗口缺口。
- etcd 对照成员健康、Raft、WAL fsync 和后端提交。已接入的 API Server 指标以同窗观测显示，保留来源和毫秒单位。

## 跨数据库调用与基础设施证据

事件页按 Trace ID 和可核对的父 Span 展示应用调用。可按应用服务、数据库引擎和纳管实例筛选。点击「查看 Trace」核对父子 Span 与耗时，点击「原始采样」检查同一实例附近的 Redis 命中和淘汰、SQL 指纹、Linux 磁盘、容器和 PVC。Redis 暂按纳管的逻辑库编号匹配，默认编号为 0。

应用上报 `db.system.name`、`server.address`、`server.port` 和可用的 `db.namespace`。当前接受 `postgresql`、`mysql`、`redis`、`etcd`、`dm8`、`kingbase`。使用前须核对地址、端口和数据库与平台资产唯一对应。Trace 只保留已列入允许范围的身份和时间字段。读取同一 Trace 的其他实例仍需要该资产的访问权限。[OpenTelemetry 数据库客户端规范](https://opentelemetry.io/docs/specs/semconv/db/database-spans/)

如已为 etcd 配置 Kubernetes Context 和 Linux node_exporter，etcd 事件会显示 API Server 侧 etcd 调用耗时、当前成员的 WAL fsync 和后端提交耗时，以及对应的原始采样。根据配置核对成员和主机身份，结合时序和原始记录复核原因。

## 按时段评估风险

在资产详情打开「风险与历史回测」。可配置 IANA 时区和工作日业务开始、结束小时，起止相同时按全天评估。达梦表空间使用率和回放差距、金仓数据库容量和回放差距、Redis 淘汰速率和未命中率、etcd 配额使用率和后端提交耗时使用同角色、同时段的历史基线。近期角色切换或有效小时不足会保留待核对状态。

影子预警先供人工确认或标记误报。确认后管理员可启用通知。修改基线时段后，新的影子预警需要重新复核。持续异常与复测回落分别保留原始采样，同一事件显示触发值、基线值、阈值和恢复读数。计划变更与维护窗口继续使用值班静默。可选模型停用或达到预算后，采集、规则预警和事件回放继续可用。

## 主备切换与写入口

从资产详情或主备相关事件打开「主备切换与写入口」。每行对应一次采样，可对照资产直连角色、控制面角色、入口会话实际落点和复制进度。配置的入口可落到不同节点，同一时段的其他观测保留各自时间戳。已记录的事件证据链接会打开原采样，随后返回同一事件。

MySQL 8.4 可在资产页使用监控账号配置写入口只读探测。全局只读状态和后端 UUID 来自实际连接，连接角色可用于核对路由。复制进度中的 GTID 追平指对应通道已经接收的事务集完成应用。其他引擎按各自的 WAL 或厂商位点呈现。
