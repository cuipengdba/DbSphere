# V0.7.0 应用 Trace 发布验收与已知限制

> 2026-11-19。此页记录 V0.7.0 的实际发布边界；更广的产品目标继续在[任务清单](DEVELOPMENT_TASKS.md)跟踪。

## 发布范围

- Go 后端接收可选的 OTLP/HTTP JSON Trace。独立写入令牌至少 32 字符；默认关闭。请求限制 1 MiB、256 Span；只留白名单字段，不保存 SQL 正文、参数、URL 和任意标签。未唯一映射到受管 PostgreSQL 资产的数据库 Span 不入资产 Trace。
- 独立 PostgreSQL 18 保存 Trace，按资产和 Trace/Span ID 去重，默认保留 7 天。Collector 分批或并发发送时，脱敏待关联父 Span 在 10 分钟内补链；未找到受管数据库子链的服务 Span 不进入资产页。
- 同一事件 ID 展示应用服务和请求 Span → PostgreSQL 客户端 Span → PG/SQL/锁或 K8S 证据、缺口、根因候选及恢复。跨服务父子 Span 可形成已观测服务调用关系。数据库侧监控、告警、规则分析不依赖 Trace 或 AI。
- 应用若能准确提供自定义 `dbsphere.pg.backend_pid`，可精确匹配锁等待 PID；若能提供 `dbsphere.pg.query_id`，且同期样本中唯一对应一个 SQL 指纹，可从 DB Span 下钻到 SQL。SQL 退化事件仅把同指纹且比事前平均慢至少 50 ms 的调用计为故障信号关联，仍不视为因果证明。
- 本版沿用 V0.6.0 的 Linux x86_64 静态 Go 服务端及一键离线容器部署，内置独立 PostgreSQL 18 镜像。目标机仍需 Docker Engine 和 Compose v2。

## 已知限制

Trace 接入目前只接受 OTLP/HTTP JSON。Protobuf/gRPC 可先经官方 Collector 转成 JSON；不接收日志和指标 OTLP。服务时间重叠与父子关系只能说明已观测链路，采样率和时钟偏移未知；受影响请求数只统计已接入且落在 100 条 Span 事件显示上限内的证据。`dbsphere.pg.backend_pid` 与 `dbsphere.pg.query_id` 是可选自定义属性，普通 SDK 不会自动提供。缺少它们时保持低置信度同窗线索或缺口，不编造精确链路。

V0.6.0 中记录的 Linux 文件系统容量映射、物理断网主机和生产 Kubernetes 验收限制继续有效。正式生产支持矩阵仍以 V1.0 的完整兼容、可靠性和安全验收为门槛。
