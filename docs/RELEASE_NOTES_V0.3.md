# DbSphere V0.3.0 发行说明

V0.3 增加跨 PostgreSQL、Linux、Kubernetes 和 PgBouncer 的规则告警、值班通知与 PostgreSQL 18 长期数据分区。平台仍支持 PostgreSQL 14–18，采用 Linux 服务端和浏览器控制台，可通过 Docker Compose 一键启动 DbSphere 与独立 PG18 存储。无需 AI 模型即可监控、告警和查看事件证据。

## 新增能力

- 默认规则覆盖 PostgreSQL 不可用、连接占用、复制延迟、锁等待、WAL 归档、Linux 资源、K8S Pod/OOMKilled/Node/PVC、PgBouncer 等信号；规则可配置严重度、阈值、持续时间和启停，变更保留版本。
- 一次故障的告警、采集错误、抑制、解除抑制、确认、恢复与升级共用事件 ID 和证据时间线。PG 连接失败与同一 Pod 的近期 OOMKilled 可归并；无关 PVC 风险生成独立事件。根因候选仍仅覆盖有限场景。
- 浏览器可创建按资产/规则限定的静默与计划维护窗。静默期间继续写入事件和证据；撤销后下一次采样恢复通知。
- 可选 HTTPS Webhook 与 SMTP 邮件，按严重度路由，持久化投递记录、失败退避、手动重试和未确认严重事件的一次性升级。未配置通道明确显示未投递。
- PG18 采样和事件按 UTC 月份分区；支持旧表迁移、小时聚合、存储占用与增长估算，以及可选保留期。未结事件及其引用证据受到保护，默认不自动清理。

## 验证范围

- [Linux 发布验收 CI](https://github.com/cuipengdba/DbSphere/actions/runs/44036215638)：6 个作业通过，覆盖单元测试、依赖审计、Linux 启动、PG18 实库存储/迁移/分区/保留期、告警事件、静默、通知、默认和外部 PG18 Compose、PG14 目标与 node_exporter。
- 本地 `pnpm test`：33 项通过，含 Webhook HMAC、重试、本机真实 SMTP 协议会话、事件确认和通知重试 API。
- 浏览器连接真实 PG18 存储：登录、维护窗、不可达测试资产、同一事件中的 `alert_suppressed` 与 `alert_unsuppressed`、未配置通道状态、存储统计均通过。
- PG14–18 的基础与诊断采集兼容、真实锁链及 K8S 只读发现/采集沿用 V0.1–V0.2 的验收记录；V0.3 默认规则的全部阈值组合未在五版及所有基础设施形态上逐项重演。

## 已知限制

- 应用 Trace、通用证据图、八类跨层确定性根因规则、巡检、SQL 指纹和可选 AI 属后续版本。当前同事件归并不等于完整应用到数据库的全链路根因分析。
- 当前通知投递按单实例部署验证；多副本并发领取、生产 SMTP 服务和真实外部 Webhook 端点仍需正式环境验收。
- 分区清理按有界行批次执行，尚未实现整分区批量卸载。生产规模升级、备份恢复和性能演练在 V0.4/V1.0 门槛中。
- 无法取得指标、权限不足或采集超时均应显示缺口；规则不能把缺失信号解释为健康。PG14 已结束上游维护，应安排升级。
